## 工程亮点（若你是来评估能力的，先看这一节）

> 这一类个人项目最容易「**做得比说得多**」。所以下面六条，**每条都给出你自己能跑一遍的命令**。

### 1. 「覆盖率 100%」是可以被追问的 —— 因为它有尺子，且尺子有出处

```
覆盖率 · 条数口径 52/52（100.0%）｜加权口径 280/280（100.0%）
platform 20/20 · 条目 72/72 · 缺口 0 · 兜底 0
```

- 不是"我做了很多命令"，而是**分母来自一张登记表**（`catalog\map.yaml`），**每个动作都要声明权重与理由**：
  权重 1~5，`weights:` 段里必须有 `why` 字段说明**这个权重是从哪句记录反推出来的**；
  写不出出处的按 `fallback` 档入账，并**在页面上标注"兜底"**（当前 26 条 `infer` / 44 条 `fallback`）。
- ★ 两条自我约束：**不设负权重**（"做得不够好"进待办，不进权重 —— 否则"越差越不重要"）；
  **不因为"当前环境跑不跑得通"降权**（目标机没装 `openssl` 不该让证书检查这项降权）。
- **复算**：起服务后 `GET /api/coverage`，或界面「覆盖率与缺口」页。

### 2. 「跑完了」和「事情成了」是两件事 —— 每个动作必须自证，且**自证要能失败**

- 每个动作都必须写断言（`verify`）：**命令全部返回 0 但断言不成立 ⇒ 任务判失败**。
- 断言的选择有一条硬口径：**判据一律问「被管的那一方」**。
  例：`kubectl scale` 返回 0 只说明 API server 收下了 ⇒ 判据改成 `readyReplicas` / `rollout status` 的**退出码**；
  「监控在采」不看配置文件、不看端口在听，只看 Prometheus **自己的** `/api/v1/targets` 里每条 `health=up`。
- ★★ 最值钱的一条反面教训：`Prometheus` 说某条告警 `firing`，而 `Alertmanager` 说它被**抑制**了 ——
  **两方回答的根本不是同一个问题**，**用错接口会得出相反的结论**。这条被钉成了永久断言。
- **复算**：`python tools\selftest.py`（834 项，含每个只读动作的真跑与结论断言）。

### 3. 「报告不许说假话」被写成了四个具体方向，并有真缺陷作样本

四个方向：**假红**（该绿的判红）· **假变更**（明明没变说变了）· **假警报**（横幅在撒谎）· **自相矛盾**（结论里有无条件的断言）。

- 样本都是**真跑当场抓到**的，不是想出来的。举三个：
  - **`parser: line_count` 挂在 `grep -c` 上 ⇒ 计数恒为 1**（十处同时中招，**离线自检一条都没抓到**）；
  - **界面在说假话**：页首写死了目标机，而执行走的是另一台 ⇒ 6 步失败却报「成功」、结论一片「（无）」，
    读起来像"装了没起来"，真相是"**这台机器上没有**"；
  - **六个老动作一直假绿**：退出码判定里带着"0 永远算成功"那半句 ⇒ 表达不了"这条命令必须失败"。
- ★ 抓到之后不止修一处：**先问「这是这一处的毛病，还是这一类的毛病？」**，
  然后**写扫描器扫全库**（`_tools\t10-audit-probe-rc.py`），最后**把其中 6 条变成永久断言**（㊽ / 🄂~🄊 / ㊾~㊿）。

- **复算**：`python tools\selftest.py --offline` —— 那一节标题就叫「T11 交付物：文档与账本不许对不上」，
  ★ 它会**实时算账本、再拿文档里的数字逐字比**：**文档写了旧数字，自检就红**。

### 4. 闸门「只增不减」，而且是**结构**而不是文档

| 闸门 | 落法 |
|---|---|
| 破坏性动作（🔴 6 个） | **必须手输确认词**，且**禁止批量**（不提供任何开关） |
| 逃生口（K8s 只读入口） | 「写命令请用对应动作」这句话**不是文档，是结构**：`verb` 是受控枚举、**没有 `flags` 参数** ⇒ `-o yaml` 物理上不可达 |
| 幂等守卫 | 一次性引导动作「**预检不成立 = 已达终态**」⇒「再点一次」成立，且**理由必须念出来** |
| 「这个集群该不该被拆」 | 观测回答不了 ⇒ 用**所有权标记文件**回答（`/etc/kubernetes/aoc-owned.json`） |
| 批量 | ★ **批量不是事务**：每台独立执行、独立留证、各自负责；失败隔离，一台上限不放大到 N 台 |

★ 命令层面还有三层防线：**参数白名单 → argv 数组（不拼 shell）→ `shlex` 逐元素转义**；
管道 / 重定向 / 命令分隔符在**加载动作时**就被拒绝。

### 5. 先规范后代码 —— 6446 行规范写着"怎么判断自己做对了"

- `repo\docs\动作规范.md`（**v1.21**）里，**每写新能力之前先定判据**，事后补记**真跑抓到的问题**；
  §12.141~§12.155 是最近一版新加的：**交付形态的本体**（把「它起没起来」变成一句**可复算**的结论）·
  **不可复现构建怎么落判据** · 启动器六种情形各有一句结论 · 认人与版本一致性 · 快捷方式的写出与撤销 ·
  ★★★ 「**跑对了**」≠「**记录对了**」（改完交付物必须再跑一次门）·
  ★★★ **「结论」这条链上只能有一个发口** · ★★★ **「拉起服务」这一跳的三条护栏** ·

  （**最近一版 T18 新增 Ⓩe Ⓩf Ⓩg Ⓩh Ⓩi Ⓩj Ⓩk Ⓩm 八条**），**断言比文字更能防回归**。

  - 起因是一个很小的现场：起草文档时我写「现有截图 **41** 张」，取数实测 **39 张** ——

### 6. 一次对话 = 一份**带证据链**的报告 —— 每条结论都能点回执行现场

一份**会话报告**里，每一条结论都挂着一个**任务号**：顺着它能看到这一步的自证、步骤留证，
以及**目标机原始输出的归档文件**。

- 三种情形**必须如实写**：`pending` ⇒ 「**未执行（人还没点确认）**」· `rejected` ⇒ 「未执行（人驳回了）」·
  复核没成立 ⇒ 「**未证实**」（不是"已完成"）；拿不到任务号的调用 ⇒ 「**没有任务号（不可回放）**」，
  ★ **不许混进结论区**。
- 时间线里**变更看得出来**：「执行（只读）」与「★ 执行（变更 · yellow）」分开标 ——
  ★ 把"改过东西"写得跟"看了一眼"一样，就是在制造错觉。
- **报告不内嵌目标机原文**：它是会被转发、贴进工单的东西；原文只以「任务号 + 归档文件名 + 取数命令」引用。
- ★ 生成前**自己扫一遍**：平台自己说的话里出现「已修复 / 已完成」⇒ **拒绝生成**（不是"生成完随它去"）。
- 另有 **源码指纹**：`GET /api/auth/ping` 上带一枚 12 位短指纹 —— 一眼看出"在跑的是哪个构建"。

**复算**：`python tools\selftest.py --offline` 的「v1.20（T17）」一节 ——

## 设计原理（为什么这么做，不是功能清单）

### 一条主线：**把"判断"从人脑搬到平台**

传统命令行运维的隐性成本不在敲命令，而在**判断**：这条输出说明什么、这台机器和那台差在哪、上次改完到底生效没有。
所以这个工作台的核心不是"把命令包装成按钮"，而是 **把判断写成可证伪的断言**：

```
预检（能不能做） → 计划（要做什么，人可看） → 执行 → 自证（用系统事实反驳） → 留证（可回放）
```

★ 这条链路**动作（Action）与配方（Recipe）共用同一个引擎** ——
所以第二阶段加服务时，**引擎零改动**：只写 YAML 与模板。

### 三条取舍

| 取舍 | 选了 | 为什么不是另一种 |
|---|---|---|
| 执行方式 | **SSH agentless + 系统 `ssh`** | 不在目标机装 agent：少一个要维护、要升级、可能失联的东西；代价是"纳管要粘一条命令"，已明说 |
| 存储 | **SQLite** | 单机单用户，起一个数据库服务是纯粹的负担 |
| 前端 | **原生 HTML/CSS/JS** | 无构建链 = 改完刷新即见；代价是手写 DOM，所以**界面不自己算结论**（结论一律来自后端） |

### 形态与安全边界

- **只绑 `127.0.0.1` 或内网**，`0.0.0.0` 由代码白名单**永久拒绝**（不是"记得别那么配"）。
- ★ **诚实标注**：**没有登录鉴权**。当前安全性完全建立在"只有本机能用"上；
  因此**任何"让 AI 在对话里执行变更"的能力（后续阶段）都必须先补鉴权** —— 这条被写成了项目红线，而不是待办。
- ★ **不做自动回滚**：只做"改动前自动备份（目标机 + 管理机双份 + sha256）+ 一键恢复（手输确认词）"。
  自动还原可能把"其实没坏"的现场一起覆盖掉，决定权留给人。

### 靶子纪律（纪律，不是功能）

一切变更**只落在自己造的对象上**（本项目统一 `aoc-` 前缀）；K8s 集群与镜像仓库**全程只读**。
★ 每条真跑都要求「**自己铺、自己收、收完自己验**」—— 收尾时用只读动作独立复核"它真的不在"，
而不是相信"我删过了"。

## 开发与验证

### 门禁怎么跑

见上面「想验证（门禁表）」。★ 两条纪律：**门禁跑不绿不算做完**；
**离线绿 ≠ 完整绿**（真的发生过：离线 574 全绿时，完整自检还有红）。

### 工程坑（都是真踩过的，写下来是为了下次不踩）

| 坑 | 症状 | 绕法 |
|---|---|---|
| YAML 标量里的 `: ` | 被当成映射，装载直接失败 | **一律用单引号显式括成标量** |
| `run` 元素里含逗号 | 被切成两个参数，命令还能返回 0 却给出合法空结果 | 加引号；**改完立刻喂装载自检** |
| 模板里的注释 | 说明文字里的裸 `{{ }}` 照样被当占位符 ⇒ 渲染报"参数未定义" | 模板里**没有注释**；要举例就写描述，**不写实例** |
| 模板占位符与配方参数名不一致 | 渲染期报参数未定义 | ★ 平台**没有**"模板变量 ↔ 配方参数"的映射层 —— 这是**结构事实**，**改名两边一起改** |
| 大文件走内联命令行 | 撞 Windows `CreateProcess` 长度上限（`WinError 206`） | 改走 `scp` + 原子 `mv` |
| 同一个大文件推第二遍 | 覆盖前的自动备份撞单文件上限 ⇒ 中止（而"第二遍"正是幂等验收要跑的那一遍） | 上传与解包做成**同一个动作**，走那条不做备份的通路 |
| 用错的接口问抑制 | 得出"抑制没生效"这个**相反**结论 | 判据问**被管的那一方**（抑制归 Alertmanager 管） |
| "探测型"步骤没声明接受非零退出码 | `grep` 没命中 = 退出码 1 ⇒ **只读动作挂着"步骤失败"，横幅在撒谎** | 探测/陈列型步骤**必须**声明它接受 `rc=1/2`；★ **`optional` 只解决任务成败，不解决横幅撒谎** |

### 改动红线

1. **命令绝不拼接** —— argv 数组 + 参数白名单 + `shlex` 转义，加载期就拒绝管道与重定向。
2. **每个动作必须有能失败的断言** —— 没有 `verify` 的动作不许进库。
3. **破坏性动作永远要人输确认词，且禁止批量** —— 不提供开关。
4. **变更只落在 `aoc-` 前缀的自造对象上**。
5. **交付一个新能力时，必须同时回填账本**（否则覆盖率会静悄悄少算）。
6. **改规范与改代码分开**：先改 `docs\动作规范.md`，再动代码。

## 参与 · 反馈 · 许可证 · 致谢

### 开发方式（★ 公开写，不隐藏、也不吹）

这个项目是**一个人 + AI 结对**做出来的，分工是明确的：

| 谁 | 负责什么 |
|---|---|
| **人（项目作者）** | 定目标与范围 · **定判据与验收标准** · 批准每一处"动真东西"的操作 · **判定"这条能不能写进交付物"** |
| **AI（开发提效工具）** | 起草方案与规范条款 · 写 YAML 与代码 · 跑门禁与真跑取证 · 写文档初稿 · ★ 但**不许自评通过** |

**防幻觉的做法**（每条都对应上面的真实事故）：
① 所有事实必须来自可重跑的命令或接口，**不许凭记忆**；
② 变更类操作**必须**留证并可回放；③ 断言必须能失败；
④ 门禁跑不绿不算做完；⑤ 数字要能被复算，且**写进文档的命令要能照抄**；
⑥ 「未跑通的能力一律不写」—— 交付物定稿前逐条标「有证据（路径）/ 无证据（已删）」。

★ 一句话：**AI 负责把它做出来，人负责判定它到底做成了没有。** 系统的设计让这句话有执行面 ——
**AI 与界面点按钮走的是同一条接口**，没有后门通道；破坏性操作永远要人来输确认词。

### 反馈与参与
