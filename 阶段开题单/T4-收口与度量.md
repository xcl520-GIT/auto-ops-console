## 2. 目标（四条主线）

### 主线 1：`host.enroll` 主机纳管（P0 级体验，**用户点名**）

用户原话（T3 期间）：

> 「以后为了用你这个平台工具，还要自己去改公钥，不是本末倒置吗」

要兑现的目标：**从"只知道 IP + 账号"到"拿到这台机器的体检报告"，全程在一个地方完成，用户不需要知道公钥是什么。**

### 主线 2：覆盖率换"加权分母"（让这个数字**经得起追问**）

现在 90.9% 的含义是"44 条登记项里做完了 40 条"。但**登记项是按"命令条数"切分的**，
和"用户平时最常干的活"不是一回事：平台能力（批量 / 备份 / 恢复 / 纳管）**一条都不算在分母里**，
可它们才是这个工作台真正的价值。→ 双口径并列 + 权重可追溯。

### 主线 3：一键体检 `checkup`（账本里登记为 P0，计划 T4）

把只读诊断项打包成**结论式报告**：一次跑完 → 「这台机器现在好不好、哪几项要处理、先去查什么」。
支持单机与**4 台并排**（复用批量框架），结果可导出。

### 主线 4：收口与演示证据 + 推送

演示手册（10 分钟讲得完）、证据索引（每条能力 → 任务ID / 截图 / 留证路径）、截图归档、README 更新、
**本阶段收尾推送一次到 GitHub 并核对 `origin/main`**。

## 3. 范围（做什么）

### 3.1 `host.enroll` 主机纳管

**界面表单**：`IP / 端口 / 登录账号 / （可选）密码 / 名字 / 角色 / 标签`

**后台流程（6 步，每步都要看得见）**：

| 步 | 做什么 | 自证方式 |
|---|---|---|
| 1 | **预检**：22 端口可达？该 IP 是否已在 `hosts.yaml`？（重复纳管要提示而不是硬覆盖） | 连通性探针 + 清单元数据 |
| 2 | **铺公钥**（见下方两条路径） | 见路径说明 |
| 3 | **生效校验**：用密钥登录跑一条无害探针（`hostname` / `id` / `uname -r`） | ★ **必须真登录成功**才算过，不接受"文件写进去了" |
| 4 | **自动登记**：写 `hosts.yaml`（`id/name/role/address/port/tags`），**写前备份原文件** | 落库留证 + 备份记录 |
| 5 | **自动体检**：立刻跑一次 `checkup`（主线 3），纳管结果页直接给这台机器的第一份体检报告 | 报告落盘 + 可导出 |
| 6 | **收口（可选）**：提示"要不要顺手关掉这台机器的 `PasswordAuthentication`"（4 台一起做，见 §10 待拍板 #5） | 变更动作自有护栏（备份 + 手输确认词） |

**铺公钥的两条路径**（★ 这是本主线唯一的技术风险点，也是 §10 待拍板 #1）：

| 路径 | 做法 | 代价 | 我的建议 |
|---|---|---|---|
| **A · 零依赖（主推）** | 工作台起一个**一次性内网分发点**（绑管理机内网 IP、**随机路径 + 一次性 token**、记录使用次数、**用完即停 + 超时兜底**），界面给出"去目标机控制台粘贴**这一条**命令"；界面**每 3 秒轮询**检测公钥是否生效（最多 120 秒） | 仍需用户在目标机控制台粘一条命令（但比 T3 那套**少一大截步骤、且全程有校验**） | ✅ 先做这条 —— 零新增依赖、当天能完成 |
| **B · 真·免手工** | 界面填密码 → 管理机自动完成密码登录 + 追加公钥 + 校验 | 取决于管理机是否有可用的**非交互密码通道**（Windows OpenSSH 通常没有 `sshpass`；`SSH_ASKPASS` 支持有限；`plink.exe` 若存在可用） | ⏳ 先**现场探明**：`plink` / `SSH_ASKPASS` / 系统 ssh 版本；能走就走，走不通就**明说原因**，不硬凑 |

> **诚实标注**：路径 A 严格说不是"零手工"，而是"**一条命令 + 全自动收尾**"。
> 它消灭的是"改公钥"这件事本身（用户不需要理解公钥），但还没消灭"去控制台粘一条"。
> 要彻底消灭，只能靠路径 B —— 所以 #1 必须用户拍板。

### 3.2 覆盖率换"加权分母"

| 项 | 要求 |
|---|---|
| 权重字段 | `catalog\map.yaml` 每条登记项新增 `weight`（1~5）+ `weight_why`（**来源必须写得出**） |
| 权重来源（优先级） | ① **用户给的"平时最常干的 5~8 件事"**（最可信）→ ② T1~T3 记录反推（用户点名/批评过的 = 高权重）→ ③ `P0=3 / P1=2 / P2=1` 兜底 |
| ★ 关键修正 | **把 `map.yaml` 的 `platform:` 段一并纳入分母**（批量 / 备份 / 恢复 / 纳管 —— 用户天天用，却不占动作条数） |
| 双口径 | 首页与覆盖率页**同时**显示：`条数口径 40/44（90.9%）` 与 `加权口径 Σw_done / Σw_all`，并列出权重来源 |
| 红线 | 权重**不许拍脑袋**：`weight_why` 写不出出处的条目，按兜底档 ③ 处理，并在页面上标出"兜底" |

### 3.3 一键体检 `checkup`

**输入**：一台或多台（4 台并排）+ 可选"快检 / 全检"

**输出（结论式，不是动作堆）**：

```
总判：🔴 1 项要处理 · 🟡 3 项注意 · 🟢 9 项通过
🔴 磁盘 / 水位        根分区 92%（阈值 85% 黄 / 95% 红）→ 先去查「目录体积排行」
🟡 时间同步           chronyd 未同步（偏移 12s）→ 「时间与时区」
...
```

**体检项（P0 初版，全部复用已有只读动作的解析器/命令）**：
时间同步 / 磁盘与 inode 水位 / 服务失败项 / 内核报错与 OOM / SELinux 模式 / 防火墙是否运行（含 `8080/9090/9100` 无主规则）/ `openssl` 与证书到期 / 包管理可用性 / 容器运行状态（docker-01）/ K8s 节点状态（三台，只读）/ **最近备份是否可用**（复用域 L，体现"护栏也是被体检对象"）

**硬要求**：
1. **缺工具/查不到 ≠ 整份报告失败** → 该项标"⚠️ 无法判定（原因 + 建议）"，其余项照常出（§1 事实 5）
2. 阈值放 `config.yaml` 的 `checkup:` 段（可改），**不写死在代码里**
3. 每项都要给"**先去查什么**"（指向对应单动作），不做纯数据堆砌
4. 导出：复用 `export.py`，一次体检 = 一份可交付报告

## 4. **不做什么**（防范围失控）

1. ❌ **自动回滚**（变更失败自动还原）—— 沿用 T3 结论：**只做"备份 + 可一键恢复"**，不做自动回滚
2. ❌ **Recipe 引擎 / 服务目录**（Nginx / Docker / MySQL / Redis）→ T5 起
3. ❌ **K8s 建集群与 K8s 管理台** → T8 / T9（T4 里三台 K8s 只做**只读体检项**，一根手指都不碰）
4. ❌ **监控告警接入** → T10
5. ❌ **登录鉴权 / 多用户 / 权限体系** → 仍是本机单用户 + 只绑内网
6. ❌ **建公开仓库** —— 公开要等**整个项目完成 + 脱敏**（T11 交付包），本阶段只推**私有**仓库
7. ❌ **在系统关键服务 / 真实业务上做验证** —— 一切验证只在 `aoc-` 靶子上（延续铁律）
8. ❌ **改 `app\` 核心代码前不先改规范** —— 本话题要动核心（enroll / checkup / 加权对账），
   照例**先补 `repo\docs\动作规范.md` 再改代码**，并在结题回执里说明理由
9. ❌ **把 `checkup` 做成"把只读动作串一遍"** —— 那样只是批量执行的马甲；它必须是**判定 + 阈值 + 下一步指引**

## 7. 验收标准（逐条可对照）

| # | 标准 | 判定方式 |
|---|---|---|
| 1 | ★ **`host.enroll` 端到端可用**：从"IP + 账号"到"体检报告"，一处完成 | 用一台**被撤销过公钥**的机器（或新 VM）当场走一遍；**全程不需要用户打开 `authorized_keys`** |
| 2 | **纳管的"生效校验"是真校验** | 反面验证：公钥故意写错（或路径不可达）→ 必须**失败并说清原因**，不许"看似成功" |

| 4 | **`checkup` 单机 + 4 台并排**，结论式 | 报告含"总判 + 每项判定 + 下一步"；**故意制造一项异常（如塞满临时目录）→ 必须判红并给出正确指向** |

## 8. 技术要点与坑（T1~T3 血泪 + T4 预判）

### 8.1 从 T3 继承的（不许再犯）

| # | 要点 |
|---|---|
| 1 | ★ **`Api` 方法存在 ≠ 接口可用** —— 新增接口**必须同时登记 `dispatch`**；自检「路由对账」会抓 |
| 2 | ★ **验证要发生在"界面真正走的那一层"**（HTTP），不能只验"底层函数能调通" |
| 3 | ★ **改完代码先重启服务再验证** —— 旧进程占着 8787 会让你误判（本轮真踩过） |
| 4 | ★ **字节比对要拿磁盘上读回的字节**（Windows 上 `write_text()` 会把 `\n` 变 `\r\n`） |
