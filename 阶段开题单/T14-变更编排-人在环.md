## 1. 目标（一句话）

> **让 AI 能"改"东西，但闸门仍然在人手里：**
> AI 只能**请求**（摆出一张写清「要做什么 / 影响面 / 怎么撤 / 撤不回来的是什么」的卡片），
> **点确认的是人**，`red` 的确认词**只能由人在界面上手输**；
> 改完必须**自证并复核**（不接受"命令返回 0"）。

★★ **本话题的主题句（拟定写进规范）**：

> **「请求」是 AI 的权利，「执行」不是。** —— AI 可以大声说要改什么、为什么、怎么撤；它一个字都不能替人点下去。

### 2.2 本次五条主线

**① 最小鉴权（硬前置 · 红线 11）**

- 新增 `app\auth.py`：
  - **口令不落明文**：`repo\var\auth.json`（`var\` 已进 `.gitignore`）只存 `pbkdf2_hmac("sha256", …)` 的 `salt` / `iterations` / `hash` / 创建时间。
  - **会话令牌不落盘**：`secrets.token_urlsafe(32)`，服务端**内存态**表（`created` / `last_seen` / TTL，默认 8h），**进程重启即全体失效**（代价：重启后要重新登录；收益：磁盘上永远没有可用凭据）。
  - **传输用 Bearer 令牌**，不用 Cookie ⇒ 天然免 CSRF、不引入浏览器 `SameSite` 差异。前端存 `sessionStorage`。
- **闸门位置**：`app\server.py` 的 `_handle()` —— 它是**唯一的请求漏斗**（静态资源、导出通道、`/api/**` 全从这里过），一处拦住全部。
  - 免鉴权白名单（最小）：`GET /` `/index.html` `/static/**`（登录页要用）· `POST /api/auth/login` · `GET /api/auth/ping`（**新增的最小探活**）。
  - ★ **`GET /api/health` 要纳入鉴权** —— 它现在会吐主机名、IP、拓扑与库规模（见本轮实测），这不是"探活"该暴露的东西。
  - 未带/错误令牌 ⇒ **401 + 完整错误信封**（`{"ok":false,"error":{...}}`）。★ T5 的教训：异常路径丢信封会把每一次拒绝降级成界面的「未知错误」。
- ★★ **首次启动无口令** ⇒ 服务**拒绝所有 `/api/**`**，只能走"设置口令"流程。
  ★ **不许"无口令 = 全放行"** —— 那是**假鉴权**，与 T7 抓到的「声明了 `deploy_confirm_text` 却没有任何 red 动作」是同一类错误（假闸门）。**这条要有断言看住。**
- **登录限速**：同 IP 每分钟 ≤ 5 次失败 ⇒ 429；连续 10 次 ⇒ 锁 60s。即使只绑 127.0.0.1，也要防本机其它程序/浏览器插件乱撞。
- ★★ **必须写清边界（不许吹）**：
  - **能防**：同机上别的用户/别的程序/别的浏览器不经登录就用这个控制台；"任何能对 8787 说话的进程"被当成执行权（§11.4 风险 1 的原始缺口）。
  - **不能防**：拿到令牌的人、拿到 root 的本地用户、内存 dump、本机键盘记录。
  - **一句话**：**这是"把门"，不是"保险柜"。**
  - ★ 同时**保留"只绑 `127.0.0.1`"**，两层叠加；**不因为有了口令就允许 `0.0.0.0`**（红线 3 不动）。

**② yellow 白名单 + `request_action`（AI 只能"请求"）**

- 工具面分层：`ToolFace` 增加 `self.yellow_exposed`（由 `config.yaml` 的 `ai.yellow_allowlist` 决定，**默认空**）。
- ★ 新增独立工具 **`request_action(action_id, host_id, params, reason)`**：
  - **它不执行**，只往新表 `ai_action_requests` 写一行（`status=pending`），返回 `request_id` + 卡片。
  - 卡片字段**全部由平台填写，不许模型自由发挥**：
    | 字段 | 来源（★ 不许是模型编的） |
    |---|---|
    | `action_id` / `title` / `risk` | 动作 YAML |
    | `host` | 请求参数 + `hosts.yaml` |
    | `params`（逐条） | 请求参数原样 |
    | **影响面** | 动作 YAML 里现成的知识（域 / 目标文件 / 服务）＋目标机角色 |
    | **怎么撤** | ★ **显式映射表**（见 §9 表）；映射不到 ⇒ **必须写"无已知撤回路径"**，不许留空、不许含糊 |
    | **撤不回来的是什么** | ★ 逐项写清；**空也要写「无」**（T7 口径） |
    | **判据** | 该动作跑完后要看哪个**只读**动作的自证 |
  - ★★ **`request_action` 的 schema 里不存在 `confirm_text`**（断言 🄋 扩展）。
  - ★ **red 动作连请求都不许发**：在 `request_action` 入口就拒，并告诉 AI「这个必须由人在界面手输确认词 —— 请把这件事说清楚，让用户自己做」。
    ★ 顺带记住 T9 抓到的坑：**被拒时必须说清"该去哪儿"**，不能只说"不行"。
- **谁来执行**：人在界面点确认 ⇒ `POST /api/ai/requests/<id>/approve`。
  ★★ **这个端点写在 `app\api.py`，不写在 `app\ai\**`** —— 这样才能**保住断言 🄌**（`app\ai\**` 不许 import 执行层 / 传输层）。AI 包里只有一张"意愿记录"，执行由 `api.py` → `engine.py` 走**既有 `/api/tasks` 同一条路**（留证 / 护栏 / 覆盖率账本三套体系自动生效）。
- **白名单第一批（✅ 已拍板定稿 2026-09-27 · 就这 10 个）**：

  | 放进第一批（可逆 · 影响面小 · 不带集群语义） | 明确**不放** |
  |---|---|
  | `pkg.install`（★ 验收①必需）· `svc.start` · `svc.restart` · `svc.enable` · `svc.reset-failed` · `svc.daemon-reload` · `sysctl.set` · `fw.port-open` · `cron.upsert` · `file.push` | `k8s.*` **全部**（含 `k8s.exec` / `k8s.kubectl` / `k8s.kubeadm-*` / `k8s.apply` / `k8s.scale` / `k8s.delete-workload` / `k8s.node-drain`）· `container.pull` · `mon.unpack` / `mon.reload` / `mon.target-*` · `sysctl.load-module` · `svc.disable` · `svc.daemon-reload`**以外**的 selinux/firewall 关闭类 |

  （`red` 6 个永远不进：`file.remove` / `pkg.remove` / `pkg.rollback` / `svc.stop` / `k8s.delete-namespace` / `k8s.kubeadm-reset`）

**③ 自证与复核（不接受"命令返回 0"）**

- 变更任务跑完 ⇒ 读 `verify_result`；**红线 10**：任何"已修复/已完成"必须挂一个 `verify_result == ok` 的任务，否则界面按**"未证实"**展示。
- ★ **复核由平台发起，不由 AI 自称**：变更完成后自动再跑一个**明确的只读动作**，问"被管的那一方"（T9 §12.37）：
  | 变更 | 复核动作 | 通过判据 |
  |---|---|---|
  | 装包 | `pkg.installed pkg=<名>` | `info` 步骤 **ok**（`rpm -q` 有输出） |
  | 卸包 | `pkg.installed pkg=<名>` | `info` **必须失败**（"package X is not installed"）⇒ ★ **"必须失败型"步骤**（T9 抓过的坑），不许判成假红 |
  | 开端口 | `net.port` / `net.firewall` | 端口真的在听 / 规则真的在 |
  | 起服务 | `svc.status` | `active (running)` |
- ★ **before / after 两份只读证据并排**（复用 T3 的 `app\changed.py` 思路），让"变了什么"看得见。

**④ 多动作组合（接 T5 的 Recipe）**

- ★ **已拍板（2026-09-27）：本期不做** —— 一次只做一个动作，**一步一张卡片**。
  理由：验收①本身就跨 yellow+red 两级，单步已足够证明这条链；组合会把"人在环"的粒度搞糊（"一个卡片批掉一串" = 把闸门合起来）。

## 3. **不做什么**（划清边界）

1. ❌ **不把 `red` 放开给 AI** —— **永远**。`red` 连"请求"都不许发。
2. ❌ **不给 AI 任何"直连 ssh / 直连 engine"的后门**（红线 6）。AI 只能走 `/api/**`，且本次是"请求"而不是"调用"。
3. ❌ **不做无人值守的自动修复**（§11.5）—— 只做"备份 + 可一键恢复"。
4. ❌ **不替代人做决策** —— AI 只负责"查清楚 + 说清楚 + 等你点头"。
5. ❌ **不做多用户 / 角色 / 权限矩阵**（本期是**单用户本地口令 + 会话**）。
6. ❌ **不接云端记忆**、不做会话云端存储。
7. ❌ **不因为有了鉴权就把服务扩到 `0.0.0.0`**（红线 3 不动）。
8. ❌ **不改掉"只绑 127.0.0.1"**、**不动 `hosts.yaml` 的靶子纪律**。
9. ❌ **不新增动作**，除非 S0 证明某条主线非新增不可（★ 扩核心代码要有出处 —— T7 口径）。
10. ❌ **不把"卡片"做成"一次点掉一串"** —— 一个卡片只对应一个动作。

> ★ 同一条铁律第三次现身：**写完判断，立刻用一条能打印出判据的命令测它。**

## 9. 技术要点与坑

### 9.1 本话题特有的坑（★ 开工前先记住）

| # | 坑 | 怎么绕 |
|---|---|---|
| **1** | ★★ **"缓存里有" ≠ "能拿到"** —— `dnf search` 成功让我误判"源是好的"（见 §4.1.1 勘误） | ★ 判"某能力可用"必须**端到端走一次真终点**（这里是 `makecache`/`repoquery`，不是 `search`） |
| **2** | ★★ **闸门最容易做成"假闸门"** | 判据不是"有没有这个字段"，而是**"把校验删掉，断言会不会红"**。★ 与 T7 的「声明了 `deploy_confirm_text` 却没有任何 red 动作」同源 |
| **3** | ★★ **`app\ai\**` 不许 import 执行层**（断言 🄌） | "AI 请求 → 执行"必须**跨包桥接**：`ai` 包只写记录，`api.py` 执行。★ 别图省事在 ai 包里 `from app.engine import ...` |
| **4** | ★ **"必须失败型"步骤** 会被判成假红（T9 抓过） | 卸包的复核里 `pkg.installed → info` **必须失败**才算"确实没了"；断言要认这种形态 |
| **5** | ★ **被拒时必须说清"该去哪儿"**（T9 抓过） | AI 请求 red 被拒 ⇒ 错误里必须写"这件事要你在界面手输确认词，AI 不能代" |
| **6** | ★ **不许把"无口令"实现成"全放行"** | 首次启动无口令 ⇒ `/api/**` 全拒 + 引导设置口令 |
| **7** | ★ **令牌/口令不许进日志、截图、Git**（红线 8 同源） | 登录请求体不打印；`var\auth.json` 已在 `.gitignore`；★ 自检里加"文件里不含明文口令"的断言 |
| **8** | ★ **`/api/health` 会吐拓扑与库规模** | 把它纳入鉴权，另开最小的 `/api/auth/ping` |
| **9** | ★ **异常路径必须带信封**（T5 抓过） | 401 / 429 / 拒绝 一律 `{"ok":false,"error":{...}}`，否则界面全变「未知错误」 |

### 9.3 撤法映射表（★ 卡片上"怎么撤"的来源，不许模型编）

| 动作 | 怎么撤 | 撤不回来的是什么 |
|---|---|---|
| `pkg.install` | `pkg.rollback tx=<本次事务号>`（🔴 red ⇒ 人手输确认词） | 装包时被**连带升级**的依赖（`dnf history undo` 会一起回退，但若被升级的包是别的服务在用的，回退会引起**服务重启**） |
| `pkg.update` | 同上（按事务号） | 旧版本 rpm 若已不在仓库 ⇒ **回不去**；被更新服务需重启 |
| `svc.start` / `svc.restart` | `svc.stop`（🔴 red） | **运行时的内存态**（连接、缓存、临时数据）—— `stop` 之后不会自己回来 |
| `svc.enable` / `svc.disable` | 反向再执行一次 | 无 |
| `fw.port-open` | `fw.port-close` | 无（但已建立的连接会断） |
| `cron.upsert` | `cron.remove` | ★ **如果覆盖了同名的既有条目 ⇒ 旧内容回不来**（除非备份过） |
| `file.push` | 用备份覆盖回去（T3 的双份备份） | 目标文件被覆盖期间的**外部写入** |
| `sysctl.set` | `sysctl.set` 回原值（原值要先读） | **运行时生效 vs 持久化生效不同**；未持久化时重启即复位 |
| （映射不到的动作） | ★ **必须写「无已知撤回路径」** | ★ 必须逐项写清 |
