## 2. 目标（三条主线）

### 主线 1：护栏地基 —— **改动前自动备份**（先做，做完才准做变更动作）

`设计\03` §3 **域 L 标 P0**、`map.yaml` 的 `platform:` 段已登记"未做"、`继续工作` 把它列为**卡点 #1**。
它是 T3 一切变更动作的前提：**没有它，改了配置就没法回退**。

要求（这四条是 §7 验收 4 的判定依据）：

1. 动作 YAML 新增 `backup:` 段（v1.2 schema 扩展）—— **声明**"本动作会改这些路径"。
2. 引擎在**执行变更前**自动把目标路径复制到目标机 `/var/backups/aoc/<任务ID>/`，**并同步回拉到管理机** `repo\var\backups\<任务ID>\`（双份）。
3. 备份记录（原路径 / 备份路径 / 大小 / **sha256** / 时间 / 任务ID）**落库**，并在界面与该任务的结论区显示。
4. 提供**恢复**能力（至少是"可照着做的恢复命令"，最好是界面一键恢复）—— 并在 T3 内做**一次真实恢复演练**留证。

### 主线 2：变更动作 ≥ 10 个（清单见 §3.2）

覆盖用户与总纲共同圈定的五类：**服务启停 / 防火墙放行与撤销 / 包安装卸载更新 / 定时任务增删 / 文件上传下载**。

### 主线 3：多机批量执行 + 横向对比

一次选 N 台机器 × 一个动作 × 一份参数 → 逐台执行 → 产出**横向对比表**（每台一行：状态 / 关键结论 / 耗时 / 是否需要人工介入）。

### 3.2 变更动作清单（提案 14 个，≥10 ✅）

> `域` 取自 `设计\03` §3 的 12 个域；`id` 为建议值，落地时可微调。
> 风险分级按规范 §2.5：`yellow` = 可恢复的变更（二次确认）｜`red` = 破坏性（+ 影响面提示 + 手输确认词）。

| # | 建议 id | 域 | 风险 | 做什么 | 备份对象 / 回退依据 |
|---|---|---|---|---|---|
| 1 | `svc.start` | E | 🟡 | 启动服务（可带 `--now` 语义） | 无文件改动；结论带**启后状态**自证 |
| 2 | `svc.stop` | E | 🔴 | 停止服务 | 无文件改动；**影响面 = 业务中断**，必须讲清 |
| 3 | `svc.restart` | E | 🟡 | 重启服务（可含 `daemon-reload`） | 无文件改动；自证 = 新 PID / ActiveEnterTimestamp |
| 4 | `svc.enable` | E | 🟡 | 设开机自启 | 记录原 `is-enabled` 状态（可回退） |
| 5 | `svc.disable` | E | 🟡 | 取消开机自启 | 同上 |
| 6 | `fw.port` | F | 🟡 | 放行 / 撤销端口（`--add-port` / `--remove-port`，永久 + reload） | 备份 `/etc/firewalld/zones/*.xml` + 变更前后 `--list-all` 快照 |
| 7 | `fw.service` | F | 🟡 | 放行 / 撤销服务（`--add-service` / `--remove-service`） | 同上 |
| 8 | `pkg.install` | H | 🟡 | 安装包（先展示依赖与体积变化再确认） | 记录 `dnf history` 事务号 → 可用 `dnf history undo` 回退 |
| 9 | `pkg.remove` | H | 🔴 | 卸载包（先展示**将被连带删除的依赖清单**） | 同上；卸载前把包清单写进留证 |
| 10 | `pkg.update` | H | 🟡 | 更新指定包（**默认只更新指定包**，不做全量 `dnf update`） | 记录事务号 + 更新前后版本号对照 |
| 11 | `cron.upsert` | E | 🟡 | 新增/覆盖一条定时任务（**只写 `/etc/cron.d/aoc-<name>`**，不碰 `crontab -e`） | 备份同名 cron.d 文件 + 变更前后 `timer.list` 对照 |
| 12 | `cron.remove` | E | 🟡 | 删除由本工作台建的定时任务 | 备份该文件（可恢复） |
| 13 | `file.push` | C | 🟡 | 从**受控目录**上传文件到目标机（覆盖前先备份） | 备份被覆盖的目标文件（走 §3.1 主线的备份机制） |
| 14 | `file.pull` | C | 🟢 | 从目标机取回文件到 `var\artifacts\`（取证 / 下载） | 无副作用 |

**计数**：🟡 12 个 + 🔴 2 个 = **14 个变更动作**（验收 ≥10 ✅）；其中 4 个只读/低风险（`file.pull` 等）作缓冲。

**为什么 `svc.stop` 是 🔴 而 `svc.start` 是 🟡**：风险分级衡量的是「**做错了会怎样**」。
`stop` 打错一个 unit 名就可能停掉生产服务，且**不支持 undo**；`start` 最坏是"没起来"。

**为什么 `cron` 只写 `/etc/cron.d/`**：改用户 `crontab` 是覆盖式写入（`crontab -`），
一旦写错就是整份任务表被替换 —— 用**独立文件**则天然可备份、可回退、可对照。

### 3.3 批量执行 + 横向对比（域 K）

| 能力 | 要求 |
|---|---|
| 选机器 | 界面上多选（4 台全选 / 任选组合） |
| 选动作 | 一个动作 + 一份参数，**对所有选中机器同一套参数** |

### 3.4 变更动作的"全套护栏"（每个动作都要满足）

| 护栏 | 要求 |
|---|---|
| 风险分级 | `risk` 必填，`yellow/red` 必带 `confirm` 段 |
| 命令预览 | 复用 T1 的预览（已含远端 `< /dev/null`，**预览长成实际要跑的样子**） |
| 二次确认 | `yellow` = 展示 `confirm.body` + 预览；`red` = 再加**影响面提示** + **手输确认词** |
| 改动前备份 | 声明 `backup:` 段 → 引擎自动执行（§3.1 主线 1） |
| 执行后自证 | `verify` 从「证明拿到了数据」升级为「**证明改动确实生效**」：<br>启停 → `is-active` + `ActiveEnterTimestamp`；防火墙 → 规则**真的出现在** `--list-all` 里；<br>装包 → `rpm -q` 版本 + 事务号；cron → 文件存在且内容可读回；文件 → 目标文件 sha256 == 源文件 sha256 |
| 全量审计 | 复用 T1 的 `ops.db` + `var\artifacts\<任务ID>\`（命令原文 / 退出码 / stdout / stderr / sha256） |

## 4. **不做什么**（防范围失控）

1. ❌ **分区 / LVM / 文件系统扩缩**（`parted` `pvcreate` `lvextend` `mkfs` `xfs_growfs`）→ 破坏性太强，推后续
2. ❌ **`rm` / `rmdir` 类删除动作** → 同上（用户已确认）
3. ❌ **内核参数写入**（`sysctl -w`、`modprobe` 持久化、`grubby`）
4. ❌ **`shutdown` / `reboot` / `kill` 进程** → 推 P2（`设计\03` 标 P2）
5. ❌ **用户 / 权限管理**（`useradd` `chmod` `chown` `setfacl`）→ 域 B，本话题不做
6. ❌ **网络配置修改**（`nmcli con mod` 改 IP/网关/DNS）→ 🔴 且**极易把自己关在门外**，推后续
7. ❌ **自动回滚**（变更失败自动还原）→ T3 只做「备份 + 恢复演练 + 可照着做的恢复命令」，**见待拍板 #5**
8. ❌ **多机"编排"**（A 机做完再触发 B 机、配方 / 依赖拓扑）→ 那是 T5 的 Recipe 引擎，T3 只做「同一动作铺到多台」
9. ❌ 覆盖率看板 / 一键体检 / 演示手册 → T4
10. ❌ 服务目录、K8s、监控告警（第二~四阶段）
11. ❌ 登录鉴权 / 多用户权限体系（仍是本机单用户 + 只绑内网地址）
12. ❌ **改 `app\` 核心代码前不先改规范** —— T3 必然要动代码（备份机制 + 批量），
    严格照 T2 的例外条款：**先补 `repo\docs\动作规范.md` v1.2（§10）再改代码**，并在结题回执说明理由
13. ❌ **在系统关键服务 / 真实数据上做验证** —— 一切破坏性验证只在 §3.1 的自造靶子上做

## 7. 验收标准（逐条可对照）

| # | 标准 | 判定方式 |
|---|---|---|
| 1 | **≥ 10 个变更动作**在界面上真跑通（含真改真回退） | 数 `catalog\actions\*.yaml` 里 `risk != green` 的（排除 demo），逐个真跑并留证 |
| 2 | **100% 有风险分级 + 命令预览** | 遍历断言：`risk` 非空；`yellow/red` 必有 `confirm` 段；预览文本与实跑 argv 一致 |
| 3 | **🔴 动作 100% 手输确认词**，且**输错不放行** | 正反两测：输对 → 执行；输错 / 不输 → 必须被拦下（**反面证据是重点**） |
| 4 | **改动前自动备份**：会改文件的动作 100% 走备份，且**恢复真的可用** | ①遍历断言：凡声明 `backup:` 的动作，任务留证里有备份记录 + sha256；<br>②**真做一次恢复演练**：改坏 → 用备份恢复 → 逐字节对照（sha256 相等） |
| 5 | **执行后自证**：100% 变更动作有 `fail` 级断言证明"改动生效" | 抽查 3 个：把 `verify` 写反 → 界面必须变红（不许"永远通过"） |
| 6 | **批量在 4 台上跑通 + 横向对比** | 4 台同参数一次执行：4 条独立任务记录 + 合并对比表（含差异高亮）+ 导出报告；<br>**失败隔离验证**：故意让 1 台不可达，其余 3 台仍须全部成功 |
| 7 | **全量自检不回退** | `selftest.py` ≥ **104/104**（T2 基线）且新增变更动作全部纳入；离线层可在机器不在线时跑通 |
| 8 | **"加动作只加 YAML" 回归仍成立** | `proof_add_action.py` 哈希 **0 变化**（备份/批量的代码改动**必须是一次性的平台改动**，不得让每个新动作都要改代码） |
| 9 | **靶子纪律** | 所有破坏性验证只在 `aoc-` 前缀的自造对象上；系统关键服务零改动（用变更前后快照对照证明） |
| 10 | **审计完整** | 每个变更动作的每次执行都能在 `ops.db` + `var\artifacts\` 里查到命令原文 / 退出码 / 输出 / sha256 / 备份路径 |
| 11 | 交接物三件齐 | 变更动作清单勾选表（做完 / 未做 / 为什么）+ 备份恢复演练记录 + 批量对比证据 |

## 8. 技术要点与坑（T1/T2 血泪 + T3 预判）

### 8.1 从 T2 继承的（不许再犯）

| # | 要点 |
|---|---|
| 1 | **退出码语义不可假设** —— 每个变更命令**先探针确认退出码**再写 `ok_exit_codes`。已知：`firewall-cmd --state` 未运行 = **252**；`journalctl -g` 无匹配 = 1；`rpm -q` 多包 = 缺包个数 |
| 2 | **会读 stdin 的命令在 SSH 链路里会挂死** —— 传输层已有 `< /dev/null`（规范 §8.5）；变更类里 `dnf` 要确认是否需要 `-y`（`BatchMode` 下任何交互提问都会卡死） |
| 3 | **别用 shell 内建**（`command -v` / `type` / `test`）—— 远端命令带 `env` 前缀 |
| 4 | **YAML 要字面量 `\t` `\n` 用单引号**；双引号会变成真字符 |
| 5 | **同一文件的多处编辑分批做**，改完立刻复核（T2 踩过一次"报了成功但没落上"） |
| 6 | **改项目文件只用 `writeFile` / `editFile`** —— PowerShell 5.1 按 GBK 读写会毁掉 UTF-8 中文 |
| 7 | **改了代码先看 `/api/health` 的 `stage/version/actions`** —— 旧进程占着 8787 会让你以为改动没生效 |

### 8.2 T3 新增的坑（预判）

| # | 坑 | 预判的绕法 |
|---|---|---|
| 1 | **SELinux 上下文**：`/root/.ssh/authorized_keys`（部署公钥）、`/etc/cron.d/` 新建文件、被 `scp` 传过去的文件，都可能因 label 不对而"看起来对、用起来不行" | 关键落点后补 `restorecon`；把 SELinux 报错（AVC）当结论展示而不是当"解析失败" |
| 2 | **`dnf` 会自己读 stdin / 需要 `-y`**，且在 `BatchMode` 下任何交互都会卡到超时 | 一律 `-y` + `--setopt=install_weak_deps=False` 明确化；`dnf` 用 `LC_ALL=C` 稳定字段 |
| 3 | **`dnf install/remove` 的耗时**远超普通动作（拉元数据 + 依赖解析） | 单步 `timeout` 单独放宽（如 300s），并在界面上显示"这一步会慢" |
| 4 | **`firewall-cmd --permanent` 后必须 `--reload`** 才生效；只加 `--permanent` 不 reload 是"看着成功其实没生效"的典型 | 自证断言必须查 **runtime 生效**（`--list-all` 不带 `--permanent`），而不是只看 `--permanent  --list-all` |
| 5 | **`--remove-port` 撤一条不存在的规则会报错** | 先查再撤，或在结论里解释"本就不存在（无需撤销）" |
| 6 | **`systemctl stop` 一个不存在的 unit 退出码非 0** | 先 `systemctl cat` 存在性检查，给出"unit 不存在，你是不是把名字写错了 + 候选列表" |
| 7 | **备份可能把磁盘写满**（大文件 / 反复执行） | 备份前测可用空间；设上限（如单文件 >50MB 需显式确认）；保留最近 N 份 |
| 8 | **`scp`/`sftp` 与 `shlex.quote` 的 argv 拼接** | 上传/下载走独立的传输通道（不经 `run` 的 argv 渲染），或严格按现有三层契约；路径必须 `pattern` 白名单 |
| 9 | **批量执行会放大错误** —— 一个写错的参数会在 4 台上同时生效 | 批量前置**预检**（连通性 + 参数校验 + 一台"干跑"预览）；🔴 动作禁止批量（见待拍板 #3） |
| 10 | **并发写 `ops.db`** | 4 台并发落库要用同一把写锁 / 串行写入，避免 SQLite 锁冲突（T2 是单机串行，没暴露这个问题） |
| 11 | **备份"成功"≠"可恢复"** | 演练必须**真的恢复一次**并做 sha256 逐字节对照 —— 否则这个护栏是纸的 |
| 12 | **变更动作的 `verify` 不能只看退出码** | `systemctl restart` 返回 0 不代表服务起来了；必须查 `is-active` + `ActiveEnterTimestamp` 变了（**变没变**是关键，不是"是不是 active"） |

## 附：T3 的一句话总结

> T1 证明了**能看**，T2 证明了**能加**（只加 YAML 不改代码，哈希 0 变化）。
> T3 要让工作台**能改** —— 但"能改"不是加几个 `systemctl` 动作就完了：
> **改动前自动备份（域 L，P0）+ red 手输确认词 + 执行后自证生效**，这三件缺一件，这个工作台就不敢用在真机器上。
> 再加**多机批量与横向对比**，第一阶段就能收口给 T4 做度量和演示。
