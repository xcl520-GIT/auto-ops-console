## 1. 目标（一句话）

> **让 AI 把"找一个东西"这件事，从"在一台机器上跑一个动作"升级为"在四台上并发找、在本地合并、给出一条带位置的结论"** ——
> 而它说的每一句话，仍然挂着 `task_id`、仍然以工作台判定为准（T12 的主题句**继续有效**）。

★ 本话题的主题句（起草时定，S1 可精修）：

> **「找不到」是一条结论，不是一句"没查到"。** —— 它必须带上「查了什么、没查什么、为什么没查」。

## 2. 范围（做什么）

### 2.1 ★★ 现状 vs 增量（**不许拿已有的当新功**）

起草前实地读了 `app\ai\runtime.py`（553 行）与 `settings.py`（100 行），**T12 已经做到的**：

| 已具备（T12） | 落点 | T13 与它的关系 |
|---|---|---|
| 单动作**多机并发 + 失败隔离** | `run_action_readonly` + `ThreadPoolExecutor(batch_workers=4)` | ✅ 复用，不改语义 |
| 按台**截断 + 计数** | `_aggregate`（`max_tool_result_bytes=4096`，每台 `max(400, limit//n)` 字节） | ★ **要升级**（见下 ②） |
| 人话 → 主机范围 | `decide_hosts`（含"哪台/各/全部"，否则**回问**） | ✅ 复用；词表回归由 ⑥ 补 |
| 缺参数**回问** | `_check_params` → `AI_NEED_PARAMS` | ✅ 复用 |
| 失败**本地翻译** | `explain_failure`（只发译文） | ✅ 复用 |
| 只发结论（A 档） | `outflow.pack_tool_result`（只取 `ALLOWED_TASK_KEYS`） | ★ **边界要在 S1 写死**（见 ③） |
| 三层暴露（域→摘要→schema） | `_select_domains` + `face.function_specs(domains)` | ★ 命中率统计由 ⑥ 补 |
| 双结论对照 + 冲突入库 | `_detect_conflicts` | ✅ 复用 |

**⇒ T13 的真实增量（六条，不能再多）**：

1. **检索式编排**：一句"找东西"的话 → **一个检索计划**（选哪几个动作 / 每个动作的参数 / 铺哪几台）；★ 与 T12 的区别是：T12 是"模型选一个动作、平台铺多台"，T13 允许**同一意图下多个互补动作**（例如"找关键字"＝ `file.grep` 多位置；"找包"＝ `pkg.installed` 全量 + **本地过滤**）。
2. **跨机聚合升级**（本地做，只回传结果）：`_aggregate` 只做"按台成列"。T13 增加**跨机合并**：**去重 / 计数 / 排序 / 生成定位表**（主机 / 位置 / 命中摘要 / 任务号），并把**回传字节数**记账（成本留证）。
3. **命中内容的出境边界写死**（★ 本话题第一条要定的口径）：检索类动作的命中内容**本来就写在 `conclusion` 里** ⇒ 出境**只走 `conclusion` 这一条既有通道**，**不新开任何原文键**（`FORBIDDEN_KEYS` 一个不许松）。★ 且会话记录里要能看出"本次结论含目标机内容"。
4. **定位式回答 + 「范围交代」结构化**：回答四要素 = **在哪台 / 在哪（路径或行号）/ 是什么 / 任务号**；新增机器可读的 `searched_scope`（**查了**：机器 × 动作 × 参数范围）与 `not_searched`（**没查**：逐条给原因，如角色挡住、动作在上限处截断）。
5. **大结果集分页（最小形态）**：★ 只做三件事 —— ① **如实标注截断**（"这是前 N 条，不是全部"，含**动作层**上限，见 §9 坑 1）② 平台侧切成**定位表分页**回传 ③ 需要更多 ⇒ **收窄范围再查**（**不**做无限续查，见 §3）。
6. **T12 遗留三项**（已拍板顺手清）：**#3 复合读去重**（`host.checkup` 与子动作同时被选 ⇒ 运行时代内去重/择一，要留证）· **#6 选域命中率统计**（本地记账，**不外发**）· **#7 真实问句词表回归样本**（≥12 条真实问句，含"各台 / 所有节点 / 统统 / 每一台"）。

**★ 两条新的事实（都不是猜的，原文已留证）**

1. ★★ **`file.grep` 的"上限"与"实际截断"分不清**：结论模板写「命中（**最多 20 条**）」，而实现是 `parser: head_lines` 取前 **20 行**（`--` 分隔行**也占行数**）⇒ 压力测试里实测只有 **12 个命中行**；★ 而且**输出被砍掉时结论里没有任何"已截断"字样**。
   ⇒ 用户问"一共命中多少处"时，平台**答不出真数**，且**无法从结论判断是否被砍**。（证据 `T13-S0-file.grep-压力-master01.txt`）
2. ★ **`file.grep` 的 `keyword` 是 ASCII 白名单**（`^[A-Za-z0-9._@+=:,/-]+$`）⇒ **中文关键字被 `PARAM_INVALID` 拒绝**："参数「关键字」含有不允许的字符：中文"。
   ⇒ 这是**能力边界**，T13 必须**如实转述**，不许含糊成"没找到"。

**★ 聚合层实测 —— 推翻起草时的判断**

`_aggregate` 的 `conclusion[:per]` 在 Python 里按**字符**切片（`len()` 同理）⇒ **中文不会被切成半个字**（用 2134 字符的超长中文实测：4 台时每台 1024 字符 + "…（已截断）"，UTF-8 往返通过）。
⇒ 真正的两个问题是：① 截断标记**不写原始长度、不写保留下多少**；② 每台配额是**字符**，而外发成本要按**字节**算（中文是英文的 3 倍）。
（证据 `T13-S0-聚合层实测.txt`）

**★ S0 里踩的两个量具坑（都是"我自己的错"，如实留着）**

1. ★ 取证脚本里**两个样例文件名相同 ⇒ 后写的覆盖了前写的**（压力测试的结论被 ② 覆盖）⇒ **留证文件名必须唯一**。
2. ★ Windows `subprocess` 默认按 **GBK** 解码 ⇒ git 输出里的中文文件名直接让 `stdout=None`（`UnicodeDecodeError`）⇒ **一律显式 `encoding="utf-8"`**（与 T12 坑 #5 同族）。

## 7. 验收标准（★ 每条都写明"怎么证伪"）

| # | 验收标准 | 怎么证伪（红得出来吗） |
|---|---|---|
| 1 | ★ **找文件内容**：一句"在某台/各台的某目录里找关键字 X" → 四台并发 → **定位表**（哪台 / 哪个文件 / 哪一行 / 命中什么 / 任务号） | 故意找一个**只在一台**存在、且**一行**命中的关键字：定位表必须**只有那一行**，且**另外三台明确写"无命中"**（不是空白、不是省略） |
| 2 | ★ **找配置项 / 状态**：一句话查到"哪台开了 X"（例：SELinux / 防火墙端口的逐台差异） | 四台结论**逐台成列**；★ 若某台动作跑不出来，必须出现在 `not_searched` 且**有原因** |
| 3 | ★ **找端口**：`net.port` 跨机 → "哪个端口在哪台被谁占、归属哪个服务" | 反例：查一个**确定没被监听**的端口 ⇒ 四台都答"没有"，并**明说"没找到"**（不许含糊成"未发现异常"） |
| 4 | ★ **找包**：`pkg.installed` 全量 + **本地过滤** → "哪台装了 / 哪台没装" | 反例：挑一个**四台都没装**的包 ⇒ 必须**逐台**说"未安装"，并交代"包名可能不同（`mariadb` vs `mysql-server`）"这类边界 |
| 5 | ★ **找日志片段**：`log.view` / `kernel.log` → "哪台的哪条日志出现过关键字，什么时候" | 反例：用一个**确定不出现**的关键字 ⇒ "没找到" + 交代查了哪些 unit / 时间窗 / 是否被截断 |
| 6 | ★★ **找不到的三段交代**：① 明说"没找到" ② 查了哪些机器 / 动作 / 范围 ③ 没查的逐条原因 | 人为构造"某台不可达 / 某动作被角色挡住 / 命中被截断"三种情形，**三种缺任何一种就算不通过** |
| 7 | ★ **成本可控**：单次检索会话 ≤ **60,000** token（超限**停下问人**，不许静默继续） | 造一个"范围极大"的问句 ⇒ 应在闸前停下并可读地说明；★ 附**聚合前/后回传字节数**对照 |
| 8 | ★ **本地聚合真的在工作**：跨机去重 / 计数 / 排序有证据 | 同一关键字在**两台**命中**同一路径** ⇒ 计数要**去重后**给数（并保留"哪两台"） |
| 9 | ★ **并发与失败隔离**：一台不可达/不存在**不拖垮**其余 | 塞一个不存在的机器名 ⇒ 其余照常出结论（复用 T12 证据形式） |
| 10 | ★ **复合读去重生效**（T12 遗留 #3） | 让模型同时选 `host.checkup` 与它的子动作 ⇒ 运行时代**去重/择一**，且回合记录里能看到"为什么跳过" |
| 11 | ★ **词表回归**（T12 遗留 #7）：≥12 条真实问句样本**全部走对**（该铺全量的铺、该回问的回问） | 样本里必须含"各台 / 所有节点 / 统统 / 每一台 / 只在某台"，**任何一条问错人就算红** |
| 12 | **命中率可查**（T12 遗留 #6）：选域命中率**本地**可见，且**不外发** | 断言：外发装箱里**没有**统计字段；统计表能在本地查到 |
| 13 | ★ **内容不变形**：结论里的中文/路径/行号**逐字**与工作台任务原文一致，截断**不许切坏多字节** | 取一条会截断的长中文结论 ⇒ 与 `task` 原文**逐字对照**，出现半个字/乱码即红 |
| 14 | ★ **外发仍只有结论**：检索内容只走 `conclusion`，`FORBIDDEN_KEYS` 一个没松 | 断言（沿用 ⑴ 的思路）对**检索类真任务**装箱：`steps/stdout/artifacts/argv` **一个都不剩** |

## 9. 技术要点与坑

1. ★★ **动作层的上限是"结论"，不是"缺陷"**：`file.grep` 只回前 20 条 —— 平台**必须如实转述**，不许把它说成"一共就 20 处"。且**不许**为了凑数去绕动作层（= 开新通道，违反铁律 8）。
2. ~~**字节切片会切坏中文**~~ ⇒ ★★ **S0 实测推翻了这条**：`len()`/`[:per]` 作用于**字符**，中文**不会被切坏**（超长中文实测通过）。真正要修的是两条：① 截断标记**不写原始长度**（只说「已截断」）⇒ 改成「保留多少 / 共多少 / 建议怎么收窄」；② 每台配额是**字符**，而外发成本要按**字节**算（中文 3 倍）⇒ S1 定字节口径。
3. ★★ **"没找到"与"没查到"必须分开**：`file.grep` 无命中返回 **1**（= 结论），而"动作跑失败"是 `failed`（= 没查到）。★ 二者在回答里**不许混为一谈**（这是 T12 主题句的续写）。
4. **范围不能自编**：`decide_hosts` 管的是"哪台"；T13 还要管"**哪条路径 / 哪个 unit / 哪个包名**"—— 后者**只能**来自用户或动作默认值，否则**回问**。
5. **回问的输出字段要齐**：T12 踩过"回问路径少返回一个字段（`outflow_tier = None`）"—— 新增 `not_searched` / `searched_scope` 后，**每个分支出口都要过一遍**（与 T6「4 条出口只改了 3 条」同族）。
6. **去重的边界**：去重只许去掉**同一动作的重复调用**与**已知的复合读重叠**；**不许**把"两台机器上同名的两个不同文件"当成重复（跨机不是跨目录）。
7. **命中率统计不许外发**：它是平台自己的账，`outflow` 装箱里不许出现。
8. **预算闸的位置**：现在在 `ask` 循环里按累计 token 判；T13 要把它变成"**停下问人**"的显式形态（S1 定：是抛错还是返回 `need_confirm`），★ 并保证**超限时已经拿到的结论不丢**。
9. **文档数字纪律**（T11 教训）：本文件里的数字都标了来源；**S0 当场复核后要回填**，不许留"看着像实测值"的数。
