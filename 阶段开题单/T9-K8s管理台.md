## 4. **不做什么**（防范围失控）

1. ★ **不建 / 不拆集群**（T8 的事）—— **默认不主动拆**；只有被搞坏时才 `k8s.kubeadm-reset` 重建
2. ★★ **不做真流式 / 不做 SSE / 不做长连接**（架构事件，**单独立题**；本话题用**快照式**并在界面明说"这不是流式"）
3. ★★ **不做交互式 `exec -it` / 不做端口转发**（同上：它们要的是一个**活着的连接**）
4. **不做 Helm / Operator / HPA / Ingress 全量 / 多集群 / 服务网格**

## 9. 技术要点与坑

### 9.1 继承下来的（**不许再犯**）

1. ★★ **"跑完了" ≠ "事情成了"**（T5/T6/T7/T8 各现形一次）—— 管理动作尤其：`kubectl delete` 返回 0 只说明**删除请求被接受**
2. ★★ **判据写对了没有，只有"它本该红"的场景才验得出来** ⇒ **每个动作都要有反例**
3 **空输出不许做非空断言**（`raw` / `lines` 的空输出 ≠ 拿不到数据）⇒ 只读动作的"必然有输出"的一步 = `get ns --no-headers`
4. **改了 `app\` 必须重启控制台**（配方可以热装载，`app\` 不行）
5. **数字必须从账本实时算**（`GET /api/coverage`），不手抄

### 9.2 T9 预判的坑（★ 开工后逐条盯着）

| # | 坑 | 先想好的对策 |
|---|---|---|
| 1 | ★★ **`kubectl get ... -A` 的输出是"分节"的**（Deployment 一段、STS 一段…） | 结论模板里**按段截图式呈现**，判读按"有没有 `0/x` 的行" |
| 2 | ★ **`kubectl get pods` 的 `STATUS` 列有十几种值**（`CrashLoopBackOff` / `ImagePullBackOff` / `ErrImagePull` / `Pending` / `Terminating` / `Completed`…） | ★ 判据**不许**枚举"坏的"（新状态就漏判）⇒ 用**"是不是 `Running`/`Completed`"**当正向判据 |
| 3 | ★ **`OOMKilled` 不在 `get pods` 的 STATUS 里**（它是 `lastState.terminated.reason`） | `k8s.diagnose` 必须取 `-o json` 的 `containerStatuses`，**不是**截屏那一列 |
| 4 | ★ **`kubectl exec` 的 argv 会被 SSH 层再剥一层** | 走 `--` 分隔 + 参数数组，**不拼 shell 字符串**（§12.41） |
| 5 | ★ **`rollout undo` 有历史深度限制**（默认 `revisionHistoryLimit`） | 结论里念出当前 revision 与能回几步 |
| 6 | ★ **drain 遇到"没有控制器的裸 Pod"会卡住** | 参数显式给 `--force` 与否的**选择**，并在结论里逐条念出被驱逐/被忽略的对象 |
| 7 | ★ **`kubectl top` 需要 metrics-server** | ★ 本环境**没有** ⇒ 相关的判据与界面**要么降级为"无法判定"、要么不承诺** |
| 8 | ★ **`aoc-t9` 命名空间删不干净**（`Terminating` 卡住） | 收尾验的不是"我发了删除命令"，而是 **`get ns` 退出码** |
