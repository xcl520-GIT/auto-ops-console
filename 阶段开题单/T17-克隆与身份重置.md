## 0. 一句话与主题句

**一句话**：把「**造一台干净靶子机**」从二十分钟的手工活，变成**一句话**。

**主题句**：**「克隆给出的是拷贝件 —— 直到身份被换掉，它才算一台新机器。」**

★ 与既有五句同族（**"命令返回 0" ≠ "事情成了"** · **"读不到" ≠ "没成功"** · **"机器起来了" ≠ "里面的服务在跑"**）。
本话题把它落在**身份**这一层：`vmrun clone` 返回 0，只说明**磁盘上多了几个文件**，
**不等于**"它是一台能被纳管、能被信任、能被审计的机器"。

## 1. 目标（一句话）

**「给我来一台干净的 Rocky 10 靶子机」⇒ 克隆 ⇒ 重置身份（machine-id / SSH host key / 主机名 / 静态 IP）
⇒ 自动纳管（`hosts.yaml` ＋ 公钥 ＋ **真登录一次**）⇒ 自动体检 12 项 —— 全程留证；
而"**克隆**"与"**删除**"永远要人亲手点头。**

## 2. 范围（做什么）

### 2.1 主线一 · `vm.clone`（新动作，🔴 **red**，人在环）

- 机制：`vmrun clone <src.vmx> <dst.vmx> full|linked`；★ **源机必须关机**（linked 需先有快照）⇒ **S0 实测**语义与退出码。
- ★★ **克隆前先给母机打快照** —— T16 结题回执 §6 明写"**克隆前先给母机打快照**是 T17 的自然前置"，本话题兑现它。
- 落盘位置：`D:\VMs\<新 id>\<新 id>.vmx`（★ 与母机同盘；余量 S0 实测）。
- ★ 不许"改名换姓偷偷来"：新机一落地就必须**可被归属判定看见**（红线 12 的延伸）。

### 2.2 主线二 · 身份重置（★ 本话题的技术核心：五项身份，逐项有判据、逐项可证伪）

| # | 身份 | 怎么做 | 判据（★ **问被重置的那一方**） |
|---|---|---|---|
| 1 | `machine-id` | `systemd-machine-id-setup --commit`（或等价），必要时重启 | 与母机**逐字节不同** ＋ 非空 ＋ 长度 32 |
| 2 | **SSH host key** | 删旧 `ssh_host_*` ⇒ `ssh-keygen -A` ⇒ 重启 sshd ＋ `restorecon -R /etc/ssh` | 新公钥指纹 **≠** 母机指纹；sshd **真在跑** |
| 3 | 主机名 | `hostnamectl set-hostname` ＋ `/etc/hosts` 的 127.0.0.1 那行 | `hostname` **回读一致** |
| 4 | **静态 IP** | NetworkManager / ifcfg（**网络是软件职责**，见关键约束） | guest `ip -4 addr` 与登记值一致 ＋ **宿主机侧 ping 得通** |
| 5 | ★★ **VMware UUID / MAC** | ★ **不许直改 `.vmx`**（红线 13）⇒ 只能靠 `vmrun clone` 自己换、或**人工在 GUI 里选**。⇒ **S0 必须实测**：克隆出的 `.vmx` 里 `uuid.bios` / `uuid.location` / `ethernet0.address` 是否已换 | 与母机不同（★ 读 `.vmx` **只读是允许的**）——「**读得到**」与「**改得动**」是两件事，写不动就**如实说写不动** |

★★ **顺序有依赖**：IP 一改，宿主机侧原本那条 ssh 就断了 ⇒ 必须**先本机身份、后网络**，
且"重启 / 断连"那一跳要**写在配方里**，不许靠人手补。

### 2.3 主线三 · 自动纳管（复用 T3 的 `host.enroll`，只加一步）

- 既有：管理机临时分发点 ＋ `authorized_keys` 注入 ＋ **真登录校验** ＋ 写前备份。
- 新增：**把新机写进 `hosts.yaml`**（含 `vm:` 登记 ＝ **归属唯一来源**，红线 12 / 规范 §12.116）。
  ★ 这是"平台改自己的配置" ⇒ **写前备份 ＋ 逐字节可回退 ＋ 对外可见**（风格沿 T7 §12.23）。
- ★ 配对：**纳管成功 = 真登录一次**，"公钥写进去了"不算成功（**"命令返回 0" ≠ "事情成了"**）。

### 2.4 主线四 · 自动体检 ＋ 新编排链（复用配方引擎，**目标：引擎零改动**）

- 复用 `host.checkup`（12 项）。
- ★ 新配方 **`vm-provision`**（`vm-cycle` **不够用**：克隆后的链多两跳）：
  `vm.clone` →（母机快照）→ `vm.start` → 等 guest 就绪 → **等 SSH** → **身份重置** → **纳管** → **体检** →（可选）关回。
- ★ 加法只加**动作 / 配方**，不新开步骤类型（`wait` 步骤 T16 已实现）。

### 2.5 主线五 · 界面 ＋ 账本 ＋ AI 面（第 12 页签「虚拟机」内扩展）

- 界面：克隆表单（源 / 新 id / 主机名 / 静态 IP）＋ **「造一台靶子机」的一键链**（每一步都看得见在跑什么、哪一步要人点头）。
- 账本：域 M 新增 `vm.*` 条目 ＋ 权重（**不搞特殊化**，与其它域同一套口径）。
- AI 面：`catalog\ai-tools.json` 重生成；★ **克隆 / 删除结构上不可请求**（与 `stop-hard` / `snapshot-revert` 同族，红线 15）。

## 3. **不做什么**（划清边界，防范围失控）

1. ❌ **不替代 VMware GUI 的职责**（虚拟网络编辑器 / vmnet / NAT 规则）（红线 17）
2. ❌ **不直接改 `.vmx`**（红线 13）⇒ ★ UUID 这件事**只能"读 ＋ 实测"**；改不了就如实说改不了，**不许**拿硬改 `.vmx` 当捷径
3. ❌ **不碰与本项目无关的 10 台 VM**（红线 12）—— 除用户**当次显式点名**
4. ❌ **不做离线写盘**（红线 14）
5. ❌ **不把"开机"做成默认行为**（红线 16）
6. ❌ **不做无人值守的批量造机**（"批量不是事务"是 T7 口径；本话题只造**一台**，N 台留给将来）
7. ❌ **不给 AI 开后门**：AI 仍**只走 `/api/**`**（铁律 8 / 9）
8. ❌ **不动 K8s 集群与监控栈**：母机**不许**是 `master01` / `node01` / `node02`，除非用户当次点名
9. ⏳ **"删 VM"要不要自动化**：**待拍板**（§10 拍板 4）—— 未拍板前一律**人工在 GUI 里删**

## 9. 技术要点与坑（★ 预判，S0~S8 逐条验）

### 9.1 带进来的口径（T16 §一.4 / §一.5，逐条找落点，不许只写在规范里）

1. **能证伪才算判据**（注入必须**真红**，且**还原后真回绿**）；2. **四级判据各归各家**；
3. **收条与判据分开写**（可能失败的那步 `optional`，判据步非 optional 且落在被管那一方）；
4. **别拿用户的环境做不可逆演示**；5. **判断不了就"跳过"，不许记成"通过"**；
6. **文档数字要"跑出来"再写**；7. **闸门只增不减**；8. **"命令返回 0" ≠ "事情成了"**；
9. **"读不到" ≠ "没成功"**；10. **「给人看的那段话」必须有断言**；11. **通道由动作声明**（`channel: ssh|local`）；
12. ★★ **同一个开口/同一件事，两处实现都要认账**（装载器 ＋ 体检 ＋ 界面 —— 只开一半就是 T16 §12.125 那条真缺陷）。

### 9.2 本话题专有的坑

| # | 坑 | 处置 |
|---|---|---|
| 1 | ★★ **身份五项漏一项就"串味"**（最阴的是 **SSH host key**：连上去**不会报错**，只会让 `known_hosts` 与审计全部失真） | 五项**逐项**一条判据 ＋ **一条"故意不重置 ⇒ 判红"的反例** |
| 2 | ★★ **UUID / MAC 可能改不动**（红线 13 不许改 `.vmx`） | **S0 实测**；改不动就**如实说**，并在规范里写成"本平台的边界"，**不许**偷偷硬改 |
| 3 | ★ **改完 IP 就把自己那条 ssh 断了** | 顺序：**先本机身份、后网络**；断连与重连**写在配方里**（`wait` + `host.wait-ssh`），不靠人手补 |
| 4 | ★ **源机不关机时 `clone` 会失败**（或行为有前提） | S0 实测退出码与话术；失败要**给下一步建议**（不是一句"失败了"） |
| 5 | ★ **目标路径已存在 ⇒ 覆盖风险** | 幂等守卫写在 precheck：**已存在 = 已达终态 / 拒绝覆盖**（**不覆盖**是硬规矩） |
| 6 | ★ **SELinux**：`/etc/ssh` 与 `/etc/machine-id` 改完要 `restorecon` | 沿用项目既有的 SELinux 处置口径，判据问被管的那一方（**不是**看命令返回码） |
| 7 | ★ **静态 IP 撞车** | 挑地址前**只读**探测（ping / arp），并把"这个地址是谁给的"写进记录（T13 定位四要素的精神） |
| 8 | ★ **`vmProbe` / `vmware.py` 的老脾气**：输出 **UTF-8**、失败 `rc=4294967295`、**错误走 stdout 且中文本地化** | 判据**只看退出码**，英文/中文关键字**一个都不许当判据**（T16 §5.4 第 12 条） |
| 9 | ★ **多出来的一台机器会改变"环境事实"**（T16 的教训：T10 监控单元不自启被照出来） | 造完机**必须体检**，"机器起来了 ≠ 里面的服务在跑"；★ 造完的机器**登记进账**，不许留"影子机器" |
| 10 | ★ **`hosts.yaml` 是平台自己的配置文件** | 写入必须**写前备份 ＋ 逐字节回退 ＋ 对外可见**；判据里有"回退后逐字节一致" |
