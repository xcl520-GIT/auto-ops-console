## 1. 目标（一句话）

**竖线已经通了，现在横着铺量**：照 `repo\docs\动作规范.md` 把 `设计\03-Linux运维命令覆盖地图.md` §3 的 **P0 只读条目做到 20+ 个**，
每个都做到「**不看终端、不查文档，这一屏就是结论**」，且每个动作都有**真能失败的 `verify`**。

判断标准（来自 `设计\03` §2）：**覆盖 = 能完整做完一件事，不是能敲一条命令**。
例：查端口要一次给全「端口 → 进程 → 归属服务 → 建议」，而不是把 `ss -tulnp` 的原始输出糊一屏。

## 8. 技术要点与坑（T1 血泪 + T2 新增）

### 8.1 T1 已证明必须遵守的（不许再犯）

| # | 要点 | 说明 |
|---|---|---|
| 1 | **远端 locale 会把字段名本地化** | 目标机 `LANG=zh_CN.UTF-8` 时 `timedatectl` 输出「本地时间」→ 按英文字段名解析得到**空字典且退出码 0**。所有远端命令走 `config.yaml` 的 `ssh.remote_env`（`env LC_ALL=C LANG=C` 前缀） |
| 2 | **`verify` 不是装饰** | 必须**真的能失败**；T1 的 6 个 bug 里有 2 个是它拦下的 |
| 3 | **退出码非 0 ≠ 没有有效输出** | 只要 stdout 有内容就**照常解析**，用 `ok_exit_codes` 显式声明"这些退出码是正常报告"（例：`systemctl is-system-running` 在 degraded 时返回 1，而 `degraded` 正是结论） |
| 4 | **优先结构化源** | `--output=json` / `ip -j` / `df -P` / `lsblk -J` / `rpm --qf` / `/proc/*`。只有在格式被发行版锁死时才写专用解析器，并在 `note` 写明理由 |
| 5 | **不要假设输出格式** | RHEL 10.0 实测 `dnf --version` = **4.20.0（DNF4，不是 DNF5）** —— 格式不可假设 |
| 6 | **解析结果必须写回 `ctx`** | `engine.run()` 里执行完步骤要 `ctx[s.name] = out.parsed`（T1 坑 #2：忘了写回 → 全绿但结论全空） |
| 7 | **表头解析别吃掉 `parts[0]`、别 `.lower()` 标签** | T1 坑 #3/#4：整列左移、key 大小写不匹配导致取不到值 |
| 8 | 别用单字母 PowerShell 函数名 | `R`/`h`/`?` 都是内置别名 |
| 9 | Windows 非 tty 下 stdout 编码 | `server.py` 的 `_fix_streams()` 已处理，新增打印不要绕过 |

### 8.2 T2 新增的坑（预判）

| # | 要点 | 说明 |
|---|---|---|
| 1 | **`ausearch` 依赖 auditd 在跑** | 未装/未跑时 `sec.avc` 不能报"解析失败"，要给**明确原因 + 建议**（`dnf install audit` / `systemctl enable --now auditd`）。这正好是验收 #3 的真实样本 |
| 2 | **`du` 不能扫全盘** | 必须限 `-x`（不跨文件系统）+ `--max-depth` + 排 `/proc` `/sys` `/dev` + 整体超时，否则一屏等到天荒地老 |
| 3 | **`find` 大文件扫描同理** | 限 `-xdev`、限制起点、限制结果条数（默认 TOP N），并明确告知"只扫了这些路径" |
| 4 | **`ss` 的进程列需要权限** | root 下可见 PID/program；非 root 会大量显示 `-` → 结论里要说明可见性来源，而不是当成"没有进程占用" |
| 5 | **端口 → 归属服务的桥接** | 用 `systemctl` 按 PID 反查 unit（`/proc/<pid>/cgroup` 或 `systemctl status <pid>`），这一步是"一次给全结论"的核心；查不到时给"无 systemd 归属（可能是容器/用户进程）" |
| 6 | **`mtr` / `traceroute` 可能未装** | `net.ping` 要**探测工具可用性并降级**（无 mtr → 用 ping + traceroute；都没有 → 说明并给安装建议） |
| 7 | **`curl` 的证书信息** | 用 `curl -sS -o /dev/null -w '%{http_code} %{time_total} %{ssl_verify_result}'`；**不要**靠解析人类可读输出 |
| 8 | **用户输入面扩大了** | 新参数（域名 / URL / 路径 / 端口 / 阈值）必须走**白名单字符集校验 + `shlex.quote`**，且断言"能还原成原 argv"（T1 踩坑 #7 的判据） |
| 9 | **SELinux Enforcing + 只读** | 只读动作在 Enforcing 下不应受影响；若某命令被 AVC 拦下，**这本身就是要展示的结论**（且它是 `sec.avc` 的真实用例） |
| 10 | **结论区 vs 原始输出区** | 结论必须精炼可读；长文本一律折叠到原始输出区（`log.view` 是这个矛盾的样板，见 2.1 第 4 条） |
