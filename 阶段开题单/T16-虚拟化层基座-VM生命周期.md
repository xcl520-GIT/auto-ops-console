## 0. 一句话与主题句

**一句话**：把工作台的手从「能 ssh 到的机器」伸到「**机器的开关**」。

**主题句候选**：**「开机是一条命令，'起来了'是一个结论。」**
（★ 与既有四句同族：**"命令返回 0" ≠ "事情成了"** —— 本话题要把它落在**电源**这一层上：
`vmrun start` 返回 0 只说明**VMware 收下了这个请求**，不等于 guest 起来了、更不等于能 ssh 进去。）

---

## 1. 目标（一句话）

**关掉的一台靶子机，工作台/AI 能把它开起来、等到真的就绪、自动体检、再关回去 —— 全程留证，
而"拔电源"（`vm.stop hard`）与"回滚快照"永远要人亲手点头。**

## 2. 范围（做什么）

### 2.1 主线一 · 宿主机执行通道（**新执行面，不走 ssh**）

| 要建的 | 要点 |
|---|---|
| `app\hostexec.py` | ★ **唯一的子进程出口**：pin `PYTHONUTF8` / `PYTHONIOENCODING` ＋ 读侧 `errors="replace"` ＋ `None` 兜底 ＋ 超时 ＋ 退出码语义（★ **T15 · S9 那颗"门禁自己红得早"的坑，不许在新通道里重演**） |
| `app\vmware.py` | `vmrun` 封装 ＋ **输出解析**（`vmrun` 是裸文本）＋ **错误翻译**（VM 不存在 / 已被占用 / 正在运行 / 找不到 vmx / Tools 不在）—— 与既有 `errors.py` 的"原因 + 建议"同风格 |
| 路径来源 | `vmrun.exe` 路径 **不写死**：`config.yaml` 的 `vm.provider.vmrun_path`（默认 `C:\Program Files (x86)\VMware\VMware Workstation\vmrun.exe`）→ PATH 兜底；找不到要**报清楚** |

★ **不碰** `.vmx`（红线 13）：一律经 `vmrun`；`inventory.vmls` **只读**。

### 2.2 主线二 · 新域 M 动作（8 个，全部进 `catalog\map.yaml` 账本）

| 动作 | 风险 | 幂等守卫（`means_done`，只写在 precheck 上） |
|---|---|---|
| `vm.list` | green | — |
| `vm.status` | green | — |
| `vm.ip` | green | — |
| `vm.snapshot-list` | green | — |
| `vm.start` | **yellow** | 「已在运行」= **已达终态** |
| `vm.stop`（**soft**，走 guest 优雅关机） | **yellow** | 「已不在运行」= **已达终态** |
| `vm.snapshot-create` | **yellow** | 同名快照已存在 = 已达终态（★ 待实测确认 `vmrun snapshot` 对同名快照的行为） |
| `vm.stop-hard`（= **拔电源**） | 🔴 **red** | **禁批量** ＋ 手输确认词 |
| `vm.snapshot-revert`（回滚） | 🔴 **red** | **禁批量** ＋ 手输确认词 |

★ **技术选择（我先定，可被否）**：`vm.stop`（soft）与 `vm.stop-hard` 做成**两个动作**、而不是一个动作的两种模式 ——
因为风险等级不同，而**风险等级在既有引擎里是挂在"动作"上的**（挂在参数上会让"red 禁批量"的判据变脆）。

### 2.3 主线三 · 编排链「开机 → 等就绪 → 自动体检 → 关回」

- 新增只读探针动作 **`host.wait-ssh`**（**轮询直到 SSH 真能跑一条探针命令**，超时判红，全程只读）
  ⇒ ★ **这样配方引擎零改动**：把"等条件成立"变成一个**动作**，而不是给引擎加一种步骤类型。
  轮询实现可复用 `app\enroll.py` 里已写好的"轮询 + 真登录校验"。
- 新增一份配方 **`catalog\recipes\vm-cycle.yaml`**：`vm.start` → `host.wait-ssh` → `host.checkup` →（可选）`vm.stop`
  ⇒ 这就是 `设计\05` 说的 **T5 配方引擎的第一个"真用例"**。

### 2.4 主线四 · 护栏从三件套升为**四件套**（新增"变更前打快照"）

- 第 4 件 = **VM 级快照**（整机回滚，比文件级备份更强）；与既有三件并列，**不是替代**。
- ★ 触发方式见 §10 待拍板（我的建议：**显式触发**，不做"任何变更前自动全域快照"）。

### 2.5 主线五 · 界面 ＋ 账本 ＋ AI 面同步

- 界面第 **12** 个页签「**虚拟机**」（列表 / 状态 / 电源按钮 / 快照）
  ⇒ ★ 必须同步 `工具\capture-screenshots.py` 的**走查表**（断言 Ⓘ 要求与界面**逐个同序**），并保持**版本对齐**前置判据。
- `catalog\map.yaml` 加域 **M** ＋ 条目 ＋ 权重（**不搞特殊化**：与其它域同一套口径）。
- AI 面：`catalog\ai-tools.json` 重新生成（green 工具面 +4）· `app\ai\requests.py` 三张表按 §10 拍板填
  ⇒ ★ `vm.stop-hard` / `vm.snapshot-revert` 必须**结构上不可请求**（不是"文档里写不许"）。

## 9. 技术要点与坑

### 9.1 ★ 从 T15 带进来的十条口径（逐条在 T16 找落点，不许只写在规范里）

1. **闸门只增不减**：`red` 确认词只能由人在界面输入；AI 侧**结构上不存在**该通道。
2. **"命令返回 0" ≠ "事情成了"** ⇒ 本话题的**主题句**（电源层的版本）。
3. **"读不到" ≠ "没成功"**：VMware 报不出 IP、Tools 不在 → 如实说"读不到"，不许空着。
4. **"给人看的那段话"必须有断言**（页签 / 卡片 / 结论）。
5. **判据只扫"平台自己生成的那部分"**，证据原样照录。
6. **别凭印象取键名**（先打出来看一眼）。
7. **还原 / 比对一律逐字节**（`read_bytes` + sha256）。
8. **中文串里一律用「」**；改完**立刻编译**。
9. ★ **判据不能判自己，也不能"看着像在看着"**：源码扫描走 **AST**；注入必须**真能红**（假绿比没有更危险）。
10. ★ **"还原 / 放回"包在 `try/finally` 里**，收尾核对**逐字节一致**；**别拿 `Select-Object -First` 截流**。

### 9.2 本话题专有的坑（预判，S0~S8 里逐条验）

| # | 坑 | 处置 |
|---|---|---|
| 1 | ★★ **`vmrun` 输出是本地代码页**（中文 Windows）⇒ 与 T15 · S9 那颗坑同源 | `hostexec.py` 唯一出口：**双向 pin 编码** ＋ `errors="replace"` ＋ `None` 兜底；**先写一条断言看住它** |
| 2 | ★★ **`vmrun start` 不阻塞** ⇒ "返回 0 = 开机成功"是**假绿** | 判据问被管的那一方：`vmrun list` ＋ guest ssh 探针；**等就绪要超时并判红** |
| 3 | ★ **`vmrun stop soft` 的等待语义**（等 guest 优雅关机 / 有超时上限） | S0 实测；超时要给**明确结论**（"请求已发出但 guest 未在 N 秒内关机"） |
| 4 | ★ **孤儿的 `.vmx.lck` 锁**（环境事件里出现过 6 个） | **只读探测可报**；★ **绝不自动清锁**（清锁 = 拿所有权 = 可能破坏正在跑的 VM） |

| 7 | ★ **快照会改变快照链**（占盘 + 影响后续回滚语义） | 默认**显式触发**（§10 拍板 3）；快照创建是 `yellow`，"能不能自动"由人定 |
| 8 | ★ **批量的含义变了**：M 域动作的"多台"是**多台 VM**，而 batch 是按 host | `red` 动作**禁批量**要在**动作级**拦住（不是靠界面不显示按钮） |
| 9 | ★ **走查表 / 版本对齐**（T15 · S10 的教训） | 第 12 页签上线时**同时**改走查工具；跑之前先对版本与同序 |
