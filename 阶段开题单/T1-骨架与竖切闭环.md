# T1 · 骨架与竖切闭环（开题单）

> 话题标题建议：`[T1] 动作台-骨架与竖切闭环`
> 所属阶段：第一阶段 · Linux 运维命令界面化
> 上游：T0（总计划）｜下游：T2（只读诊断动作铺量）

---

## 1. 目标（一句话）

**先竖着打通一条线，再横着铺量**：让「界面点一个动作 → 后端经 SSH 在目标机执行 → 结果返回 → 落库 → 可回放」这条链路完整跑通，并证明 **新增一个动作 = 只加一份 YAML，不改代码**。

## 2. 范围（做什么）

1. **后端服务骨架**：Python 3.12 标准库 `http.server`；只监听 `127.0.0.1`（或内网）；路由分层（接口 / 领域 / 执行 / 存储）。
2. **动作引擎 v1**：加载 `catalog/actions/*.yaml` → 校验参数 → 渲染**命令预览** → `precheck` → 执行 → `verify` 自证 → 落库。支持 `risk: green/yellow/red` 分级（T1 只有 green，但机制与样例要在）。
3. **执行层 v1**：系统 `ssh -o BatchMode=yes`（密钥 + `ControlMaster` 复用）；超时、退出码、stdout/stderr 分流；**所有参数必须来自结构化定义，禁止字符串拼接用户输入**。
4. **主机清单 v1**：`hosts.yaml`（或 SQLite）；含 SSH 连通性自检。
5. **存储 v1**：SQLite（`tasks` / `task_steps` / `artifacts`）；原始输出归档到 `var/artifacts/`；界面可按任务回放。
6. **前端 v1**：单页——动作列表 / 参数表单（带说明与默认值）/ 命令预览 / 执行 / 结果区 / 历史列表。
7. **三个动作（竖切样本，覆盖三类形态）**：
   - `host.overview` 主机概览（**一次给全结论**：发行版、内核、CPU、内存、负载、运行时长）
   - `svc.list` 服务总览（谁在跑、谁失败、失败原因）
   - `log.view` 日志查看器（**带参数**：unit / 时间范围 / 级别 / 关键字）
8. **自检脚本** `tools/selftest.py`：服务能起、动作能加载、目标机能连、三个动作能跑通。

## 3. **不做什么**（防范围失控）

1. ❌ 变更类动作（服务启停、防火墙放行……）→ T3
2. ❌ 多机批量执行 → T3
3. ❌ 覆盖率看板 / 一键体检 → T4
4. ❌ 服务目录、K8s（第二、三阶段）
5. ❌ 登录鉴权（本机单用户）——**但必须绑 `127.0.0.1`，不允许 `0.0.0.0`**
6. ❌ 自研图表库（T1 只做表格与文本结果）

## 7. 验收标准（逐条可对照）

| # | 标准 | 判定方式 |
|---|---|---|
| 1 | 3 个动作在界面上跑通，**结果与手工执行一致** | 贴对照证据（界面结果 vs 终端原命令输出） |
| 2 | 每次执行都落库：命令原文、起止时间、退出码、stdout/stderr | 查 SQLite + 回放一次 |
| 3 | 风险分级机制存在，且有一个 `yellow` 样例可用 | 展示样例 YAML 与二次确认界面 |
| 4 | **新增第 4 个动作只需加一份 YAML** | 附 git diff：只有 1 个新增文件 |
| 5 | 目标机不可达 / 命令失败时，界面给「**原因 + 建议**」，不是裸 stderr | 断开目标机复现一次 |
| 6 | `python tools\selftest.py` 一条命令跑完并通过 | 原始输出留档 |

## 8. 技术要点与坑

| # | 要点 | 说明 |
|---|---|---|
| 1 | **命令注入** | 参数必须来自结构化定义 + 白名单校验；**绝不拼接**；`ssh` 用数组传参不拼字符串 |
| 2 | **首次连接的主机指纹** | `BatchMode=yes` 下遇到未知主机键会直接失败 → 需预置 `known_hosts`，或提供显式的「信任此主机」动作 |
| 3 | **不要解析人类可读输出** | RHEL/Rocky 10 的 `dnf` 已是 DNF5，输出格式与旧版不同；一律用退出码 + 结构化数据 |
| 4 | **SSH 连接复用** | 用 `ControlMaster/ControlPersist` 省握手开销（agentless 的代价补偿） |
| 5 | **4GB 管理机** | 后端只用标准库；前端无构建链；不引入 node_modules |
| 6 | **幂等与留证** | 每个动作必须写 `verify`（用系统事实验证结果），而不是"执行完就假定成功" |
| 7 | **时区与时间** | 所有落库时间用统一时区（`Asia/Shanghai`）；`journalctl` 默认 UTC 要注意 |
