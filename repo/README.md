# auto-ops-console · 控制台本体

> 把 Linux 运维从「敲命令」变成「点界面」，并且**每一步都留证、可回放**。
> 本目录是**可运行的控制台本体**；项目根目录还有交付文档（`README.md` / `工程方法.md` / `技术实现.md` / `CHANGELOG.md`）。

> ★ **公开前必须脱敏** —— 本文件与 `config.yaml` / `hosts.yaml` 里含有**内网地址与主机名**、
> 以及**真实环境的版本与状态**。公开前必须按项目根 `工程方法.md` 的「发布前检查」逐项替换为示例值。

**体检的 12 项**：时间同步 / 磁盘水位 / inode 水位 / 服务失败项 / 内核报错与 OOM / SELinux 模式 /

设计要点：**缺工具 ≠ 整份报告失败**（该项标「⚠️ 无法判定 + 建议」，其余项照常出）；
每项都给「**先去查什么**」，指向对应单动作，不做纯数据堆砌。

## 快速开始

```powershell
cd <你的路径>\auto-ops-console\repo

# 1) 装载自检（不起服务，先确认配置 / 动作 / 数据库 / 主机清单都能装载）
python -m app.server --check

# 2) 起服务（只监听 127.0.0.1，符合项目安全红线）
python -m app.server
#    → 浏览器打开 http://127.0.0.1:8787/
#      ★ 页首会显示当前版本，例如「T18 · v0.16.0」—— 用来确认你跑的是哪一版

# 3) 自检（离线层不连目标机；完整层会在目标机上真跑若干只读动作）
python tools\selftest.py --offline     # 752 项
python tools\selftest.py               # 834 项（约 3 分钟；需要 4 台在册机可达）
```

**依赖**：Python ≥ 3.11 + 项目内嵌 PyYAML（`vendor\`）+ 系统 `ssh` 客户端（`ssh` / `scp`）。
前端是原生 HTML/CSS/JS，**没有构建链、没有 node_modules**。

**改完代码记得重启服务** —— 8787 上挂着旧进程会让你误判（真踩过）。

## 三条架构红线 + 一条纪律

1. **只绑本机/内网** —— `config.validate_bind()` 用白名单前缀校验，`0.0.0.0` **永远拒绝**。
2. **命令绝不拼接** —— 动作里的命令是 **argv 数组**；参数先过白名单正则，最后由 `shlex.quote()`
   逐元素转义。禁止管道 / 重定向 / 命令分隔符，**加载动作时就拒绝**。
3. **执行完不许假定成功** —— 每个动作必须写 `verify`，用系统事实自证；
   断言不成立 → 任务判 `failed`，**即使所有命令都返回 0**。
   （配套经验：**"某物不存在"必须由退出码承担**，不能写成 verify 的非空断言 —— 规范 §9.6）

★ **靶子纪律（纪律，不是红线，但同样不许破）**：一切变更**只落在自己造的对象上**
（本项目用 `aoc-` 前缀：`aoc-lab.service` / `aoc-fail.service` / `/opt/aoc-*` / `/etc/cron.d/aoc-*`）。
**K8s 集群与 Harbor 全程只读，一根手指都不碰。**

## 加一个新动作

**只需加一份 YAML，不要改 `app\` 下的任何代码。**
（回归证明：`python tools\proof_add_action.py` → **66 个文件 0 变化**，且它会**真跑一次**新动作再删掉临时文件）

1. 读 `docs\动作规范.md`（尤其 §5 与 §10.3.5 的检查清单）
2. 在 `catalog\map.yaml` 登记（如果还没有）+ 给权重行（`weights:` 段，必须有 `why` 出处）
3. 新建 `catalog\actions\<域>.<动作名>.yaml`，**文件名必须等于 id**
4. 命令优先选结构化输出：`--output=json`、`-p KEY`、`/proc/*`、`--no-legend`
5. 写 `verify`（至少一条，且要真的能失败）
6. 写 `conclusion`，目标是「不看终端、不查文档，这一屏就是结论」
7. `python tools\selftest.py --offline` 全绿后再真跑

**加一个服务（配方）**：`python tools\new-recipe.py` 生成骨架 → 填空 → `python tools\recipe-check.py` 体检。
★ 配方里**没有一处命令或逻辑**：配置与模板走 YAML + 模板目录，判定与分支一律走平台侧。

**★ 几个已记录的坑**：YAML 标量里出现 `: ` **必须加引号**；`run` 元素里含逗号**必须加引号**；
**模板里没有注释**（说明文字里的裸 `{{ }}` 照样被当占位符）；**模板占位符必须与配方参数逐字一致**
（平台**没有**映射层，这是结构事实）。

## 覆盖率账本怎么读（双口径）

页首一行同时显示两个口径，**不允许只显示其中一个**：

```
覆盖率 · 条数 52/52（100.0%）｜加权 270/270（100.0%）· P0 28/28
```

- **条数口径**：登记一项 = 一个动作，做完算一分。保持与历史可比。
- **加权口径**：把**平台能力**也算进分母（批量 / 备份 / 恢复 / 纳管 / 回放 / 导出 / 配方引擎 / K8s / 监控…）。
  权重 1~5，**每条都必须在 `weights:` 段写得出 `why` 出处**；写不出出处的按 `fallback` 档并在页面标"兜底"。
- ★ **权重是反推的，不冒充用户原话**（页面上明写）。当前分布：`infer` 26 条 / `fallback` 44 条。
- ★ 两条禁令：**不设 −1**（"做得不够好"进待办，不进权重，否则"越差越不重要"）；
  **不衡量"当前环境跑不跑得通"**（`openssl` 未装不该让 `sec.cert` 降权）。
- ★ **交付一个新能力时，必须同时回填账本**：`entries` 段靠"动作文件是否存在"自动对账，
  而 `platform:` 段是**显式布尔 `done`** —— 没有任何机制会替你发现它没更新。
  （真实教训：`host.enroll` 交付后 `done` 忘了改，页面少算 5 分权重。）

## 已知限制（诚实清单）

| 限制 | 说明 |
|---|---|
| 无登录鉴权 / 无多用户 | 本机单用户，靠"只绑 127.0.0.1"兜底。登录鉴权不在当前阶段范围 |
| 纳管仍需在目标机粘一条命令 | 管理机是 Windows OpenSSH，**没有可用的非交互密码通道**（`sshpass` / `SSH_ASKPASS` 支持有限）→ 走零依赖路径 A；"填密码全自动"已评估后**明确不做** |
| 无自动回滚 | **设计决定**：只做"备份 + 可一键恢复"。自动还原可能把"其实没坏"的现场也覆盖掉 |
| `ControlMaster` 在 Windows 不可用 | Windows 的 OpenSSH 不支持 Unix 域套接字；部署到 RHEL 管理机后自动启用 |
| 无流式推送（SSE） | 动作都在秒级完成；K8s 日志是**快照不是流式**，界面与结论里都明说 |
| Grafana 首次登录要改密 | `admin/admin` 强制改密，★ **这一步只能人做** —— 报告与界面都**明说了**，没有假装完成 |
| 监控与被监控同机 · 收端与 Alertmanager 同机 | ★ **共因故障**：本环境只有 4 台机器，**做不了两全**。这是为"不让监听面扩大"付的代价，**收益是结构性的、代价是可观测的** |
| 部分动作在缺组件的机器上"无法判定" | 例：`sec.cert` 需要 `openssl`、`db.mariadb-ping` 需要 `mariadb-admin`。★ 判据是「未成功 **且** 原因+建议齐全」，**不是"必须成功"** |
| 环境依赖内网可达 | 目标机在 `192.0.2.0/24`；换环境需改 `hosts.yaml` 并重跑靶子脚本（`var\lab\`） |
