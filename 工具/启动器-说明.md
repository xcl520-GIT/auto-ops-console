## 1. 怎么用

| 你要做的事 | 怎么做 |
|---|---|
| **启动** | 双击 `工具\AutoOpsConsole.exe` |
| **停止** | 双击 `工具\停止控制台.cmd` |
| **重启**（改完代码后） | 双击 `工具\重启控制台.cmd` |
| **建快捷方式** | `AutoOpsConsole.exe shortcut add`（桌面 ＋ 开始菜单） |
| **撤快捷方式** | `AutoOpsConsole.exe shortcut remove`（★ **只删自己建的**） |
| **看它现在什么状态** | `AutoOpsConsole.exe status`（或双击，已在跑就只开浏览器） |

命令行同样的东西（有时更好用）：

```powershell
$exe = "E:\LOBEHUB_work\项目库\auto-ops-console\工具\AutoOpsConsole.exe"
& $exe status                       # 只看状态
& $exe status --json                # 一行 JSON（给脚本读）
& $exe stop ; & $exe restart
& $exe shortcut list                # 审计：我建过什么、指向哪、工作目录是哪
```

### 1.1 参数（★ 全部可注入 —— 这不是"功能"，是**判据的地基**）

| 参数 | 环境变量 | 默认 | 为什么要有 |
|---|---|---|---|
| `--port N` | `AOC_PORT` | `8787` | ★ 判据要在**临时端口**上跑真身，否则一测就动到**你正在用的那个控制台**（「判据不许伤到环境」） |
| `--logdir P` | `AOC_LOGDIR` | `repo\var\logs` | 同上：判据要能在**完全不碰**真实日志目录的条件下跑真身（连删都不删） |
| `--shortcut-dir P` | `AOC_SHORTCUT_DIR` | 桌面 ＋ 开始菜单 | 同上：否则测"建/撤"只能往你**真的桌面**上写东西 |
| `--json` | — | 关 | 只输出一行 JSON；★ 同时**不留窗口、不等按键、不弹浏览器**（否则脚本会**挂死在 `ReadKey`**，或在你的桌面上弹窗） |
| `AOC_ROOT` | — | 自动认路 | 明确指定项目根（不依赖它被放在哪） |

★ 优先级：**命令行 > 环境变量 > 默认值**；结论里**回显实际用的那个**（端口 / 日志目录）。
★ **默认值是给界面看的，不是给脚本看的** —— 脚本请**点名**。

> ★★ **S8 真跑照出的两条**（都已修，见 §7）：
> ① `AOC_SHORTCUT_DIR` 原来是**帮助里承诺了、代码里没有**（只有 `--shortcut-dir`）—— 那句话是**假话**；
> ② 显式 `--port 8787` 会被 `AOC_PORT=9999` **反超** —— 优先级写反了。

### 1.2 退出码（★ 给脚本读的那一半）

| 码 | 含义 |
|---|---|
| `0` | 在跑，且是我们的控制台 |
| `3` | 端口有监听，但**不是**我们的（旧版本 / 别的程序）—— ★ 两者**分开报**，处置完全不同 |
| `4` | 没在运行（端口上没有监听） |
| `5` | 在跑，但**跑着的不是磁盘上那一版**（T13「跑的是旧代码」那个坑） |
| `1` | 命令本身失败（参数错 / 启动失败 / 停止超时） |

★ **这张表是合同**：`start` / `stop` / `restart` / `status` 遇**同一情形**必须给**同一个码**。
  S8 之前 `start` 撞上"别人的程序占着"给的是 **1**（表里写 3）⇒ 脚本**分不出**
  「端口被别人占着（要去找人）」和「参数写错了（要改命令）」。现在四个入口口径一致。

★ `--json` 的**字段是固定的**（没有的给 `null`）—— 它与「**恰好一行**」是同一条纪律，
  脚本才敢**按键取值**，而不是先看这一行有没有那个键。核心字段：
  `ok` · `action` · `port` · `port_source` · `state` · `pid` · `version` · `stage` ·
  `disk_version` · `disk_stage` · `configured` · `browser` · `error` · `reason` · `exit`。

## 2. 它替你做了什么（★ 这才是"设计"，不是"包一层命令"）

| # | 行为 | 原来的痛 |
|---|---|---|
| ① | **幂等**：已经在跑 ⇒ 不重复起，直接开浏览器 | 起两次 ⇒ 端口冲突，报错还看不懂 |
| ② | **认人**：端口被占着但不认 `/api/auth/ping` ⇒ 是**我们自己的旧版本**就换掉；**不是我们的**就拒绝动手并说清原因 | 「跑的是旧代码」这个坑 T13 踩过一次 |
| ③ | **找解释器**：`AOC_PYTHON` → PATH → 常见位置（每个都真跑一次 `--version`） | 见 §3.1 ★ 如实说：本机实际靠**硬编码兜底** |
| ④ | **不依赖任何窗口**：后台拉起（`CreateProcess` ＋ `CREATE_NO_WINDOW`），日志写 `repo\var\logs\console-<端口>.{out,err}.log` | 关掉那个黑窗口 = 服务没了 |
| ⑤ | **等就绪**，不是"睡 3 秒"：轮询**免鉴权**的 `/api/auth/ping`，最多 45 秒 | 起来没起来看不出来 |
| ⑥ | **成功不留窗口、失败留窗口**，并把日志末尾几行贴出来 | 失败时窗口一闪而过，啥都看不到 |
| ⑦ | ★ T18：**报出版本一致性** —— 「跑着的那个进程是哪一版」vs「磁盘上是哪一版」 | T13/T15 都踩过"跑的是旧进程而看不出" |
| ⑧ | ★ T18：**快捷方式可建 / 可撤 / 可审计** | 建了不知道建在哪、想撤不知道撤哪个 |
| ⑨ | ★★ T18·S8：**结论只发一次，且字段固定** | 此前 `stop` / `restart` / `shortcut` / 失败的 `start` 会**发两行** JSON，而"恰好一行"正是脚本那一半赖以成立的东西 |
| ⑩ | ★★★ T18·S8：**日志文件名带上端口**（一个端口一个实例、一个实例一组日志） | 两个实例抢同一个 `console.out.log` ⇒ **后起的那个被静默掐死**（`cmd` 打不开重定向目标 ⇒ 子进程根本没被拉起来），而结论还说"服务没能在预期时间内回应"（**假话**），白等 138 秒 |
| ⑪ | ★★ T18·S8：**拉起前一秒确认"日志写得进去"**，不写就**立刻**说清楚 | 把上面那条从"138 秒的假结论"变成"**1 秒的真话**" |
| ⑫ | ★★ T18·S8：`--logdir` **指到已存在的文件**不再崩；超时**分开报**「**没起来**」与「**起来了不回应**」 | 此前是**未捕获异常**（没有结论、退出码是个 .NET 异常码 `0xE0434352`）；两件事都被写成同一句话 ⇒ **最该说的那件（它根本没启动）被说丢了** |

★ 另外三件它**刻意不做**的事（是纪律，不是能力不足）：

- **不写任何凭据**：模型 key 从来不落盘（红线 8），控制台口令也不落它手里（红线 11）。
- **不动别人的进程**：端口被一个**不是本控制台**的程序占着时，它**只报告、不杀**。
  ★ 这条在 T18·S4 才真正做到「**每一道口子都认账**」—— 此前 `stop` / `restart` 是不认人的
  （`start` 会拒绝的东西，`restart` 会把它杀掉）。**拒绝时不提供 `--force`**：那是纪律。
- **不改绑定地址**：控制台必须仍绑 `127.0.0.1`（红线 3）。启动器碰不到这件事
  —— 地址由 `app\config.py::validate_bind` 在平台侧把关。

## 3. 它是怎么编译出来的

```powershell
工具\build-launcher.cmd        # ← 一条命令，不装任何东西
```

本机自带 .NET Framework 的 C# 编译器就够（`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`）。
脚本会打印**源码 sha256 / 产物 sha256 / 产物大小**。

### 3.1 ★★ 两件必须如实说的事

**（一）这个产物**不可复现**。** 同一份 `.cs` **连编两次，hash 两两不同**（大小相同）。
根因是老 `csc` 的**非确定性构建**（PE 头带时间戳等）。
⇒ 所以验收口径是「**大小一致 ＋ 行为等价 ＋ 源码 sha256**」，**不是**产物 hash 逐字节相等
（规范 §12.142）。**反过来说：别用 hash 判断这个 exe 有没有被换过，要看行为。**
⇒ 实测（T18·S8，★ 脱敏后重建过一次，数字随之更新）：`工具\AutoOpsConsole.exe` **34816 字节**，
   第 1 次编 `538d8520…` → 第 2 次 `f1d760b0…`（**同一份源码，两个不同的哈希**）。

> ★★ **源码 sha256（「这份源码」唯一的可复算名字）**：
> `404558f2384fa95107ce48a5cf525d004171817cfdc131b3b948a8f1c616e3fe`
> ★ **改了 `.cs` 就必须更新这一行** —— 自检断言 **Ⓩg-5** 拿它和磁盘上的对账，
> 不一致就红（"改了源码但没更新记录"这件事，从此有人看着）。

**（二）★★ 「自动找解释器」现在是**真的自动**（六层探测）—— 但**如实记**它曾经不是。**
实测（T18·S0 §0.3，改造前）：候选只有四条，最后的兜底是
`D:\Python311\python.exe`（**一条硬编码的机器专属路径**，3.11.9）。
**真正起作用的正是那一条** —— 换台机器 / 换目录就找不到。
★ 而 PATH 上的 `python` 是 `…\WindowsApps\python.exe`（**Length=0 ＋ ReparsePoint**，
是**微软商店的执行别名占位**，不是解释器本体）。

⇒ T18·S9 改成**六层**（顺序讲得通，兜底排在最后）：
`AOC_PYTHON`（人点名）→ PATH 上的 `python` / `python3` → **`py -3`**（★ Windows 官方 Python Launcher，
**不受商店别名干扰**）→ `%LOCALAPPDATA%\Programs\Python\Python3*` → `%ProgramFiles%\Python3*` →
（最后）那条硬编码路径（★ 注释写清"它不通用"）。

> ★ **2026-09-29 补记（脱敏之后）**：第 ⑥ 层那条硬编码路径，在**公开版里是中性占位** ——
> 原始的本机专属路径属于**本机标识**，脱敏时已按规范 §12.158 替换掉 ⇒ **它在本机并不成立**，
> 本机实际由第 ③ 层 **`py -3`** 命中（指向 3.11.9）。
> ★ **换机器请用 `AOC_PYTHON` 点名**解释器，别指望这一层。
> ★ `.cs` 里那句注释（"本机解释器在这"）在公开版里**已不成立** —— **如实记在这里**，
> 暂未改源码（改 `.cs` 会牵动重建与源码 sha256 对账，属另一个动作）；★ **别把那句注释当本机事实读**。
★ **必须校验 3.10+**（本项目代码用了 `X | Y` 类型写法），"版本太低"要**跳过并继续找**。
★★ **"跳过"要能被看见**：结论里报出**用的是谁 · 什么版本 · 在它之前跳过了几个候选**
（`--json` 的 `python` / `python_minor` / `python_skipped`）。
★★ **真跑实测**（`T18-S9-解释器探测.txt`）：① 不点名 ⇒ 自动找到 `python`（3.11）；
② 把 PATH 砍空 ⇒ **回落到 `py -3`**（3.11）—— 这正是"换台机器也找得到"的那条路。

★ 另注：总纲「关键设计约束」写的是 **Python 3.12 标准库优先**，而实测解释器是 **3.11.9**
（T1~T17 全部是在 3.11.9 上验证的）。**文档与环境不一致这件事本身，也要如实记着。**

**（三）`build-launcher.cmd` 必须保持纯 ASCII。** 新坑（T18·S2 实测）：
cmd 按 **OEM 代码页**读 `.bat`（`chcp` 管不住它），非 ASCII 字节会把命令行切碎 ——
实测报 `'Y' is not recognized` / `'et' is not recognized` / `'hinese' is not recognized`。
⇒ 规矩：**整个 `.cmd` 零个非 ASCII 字节**（连 `rem` 里也不许有）；中文说明写在本文档里。
（`停止控制台.cmd` 侥幸没事，是因为它把中文只放在 `rem` 里 —— 那是运气，不是规矩。）

**（四）★★★ 拉起服务的方式是 `CreateProcess(bInheritHandles = FALSE)`，不是 `Process.Start`。**
T18·S8 真跑照出一条**交付能力**上的硬伤：`Process.Start(UseShellExecute = false)` 传的是
**`bInheritHandles = TRUE`** ⇒ 子进程继承"本进程里**所有可继承的句柄**"，
而 `.NET Console` 首次使用 stdout 时会 `DuplicateHandle(..., bInheritHandle: true)` 出一份
**可继承的拷贝**（我们拿 `GetStdHandle` **清不掉它**）⇒ `cmd.exe` 一直攥着**调用者给启动器的
stdout 管道** ⇒ ★★ **任何用管道收启动器输出的脚本，永远等不到 EOF。**
★ 真跑定位（四组对照）：`stdout` 收管道 ⇒ **挂住 180 秒**；`stderr` 收管道 ⇒ **2.4 秒返回**
（因为启动器**从没写过 `Console.Error`**，那份拷贝压根不存在）。
★ 为什么这条对交付形态是要害：**"下载安装即可用"的前提是"能被脚本 / 接口型地调用"**，
而一个"凡是被管道收取输出就挂死"的启动器做不到这件事。
★ 诚实记一笔：**第一次修法不彻底** —— 只给子进程加两条它自己的管道（`RedirectStandardOutput`），
被继承出去的那一份**并没有收回**，真跑照样卡死。**修"结果"不修"根"，症状一点也不少。**

## 4. 它自己怎么被验证（★ T18 的新东西）

```powershell
cd repo
python tools\launcher_probe.py          # 人话（98 条判据）
python tools\launcher_probe.py --json   # 一行 JSON（给自检读）
```

★ 为什么要有它：启动器跑在 `repo\` **之外**，两道门扫不到它 ⇒ 它的行为此前**一条判据都没有**。
★ ★ 它**全程跑在临时端口 ＋ 临时目录**（端口 / 日志 / 快捷方式落点都可注入），
**从不扰动你 8787 上正在用的那个控制台**。
★ 它断言的是**不变量**（"退出码与状态自洽"、"注入之后人话里不许再出现 8787"…），
不是"这台机器上控制台正在跑"这类**环境事实**。
★ ★★ T18·S8 补上的一跳：**真 `start` 到就绪 → 幂等 → `restart` → `stop` → 再 `stop`**。
  ★ **隔离**：`start` 之前先把 `repo\`（**不含 `var\`**）拷成**临时 root**，
    那个实例的库 / 日志全落在临时目录里 ⇒ **不碰生产库**（判据会核对
    `repo\var\ops.db` 的 sha256 **前后一致**；★ 若此刻 8787 上真有控制台在跑，
    这一条**如实跳过**并说明"这一条这次验不到" —— 不拿环境当判据）。
  ★ 解释器取自 **`sys.executable`**（探针自己跑在哪个解释器上，就把那个交给启动器），
    所以这一组**不依赖本机那条硬编码的 `D:\Python311\python.exe`**（§3.1 二）。
