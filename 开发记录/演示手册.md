## 档一 · 30 秒电梯

> **一台 Linux 机器出问题，你要 ssh 上去敲七八条命令，散落在终端历史里；改一个配置，改前没备份；
> 四台机器要同看一眼，得开四个窗口；新机器要加进来，得自己去改公钥。**
>
> 这个工作台把「**要敲的命令 + 要做的判断 + 要留的证据**」收进一个界面 ——
> **每一步都能回放，每一句结论都能被系统反驳。**

三个数字（★ 页首一眼可见，且都能一条命令复算）：

```
动作 118 个（66 只读 · 43 可恢复 · 9 破坏性）｜ 配方 12 份 ｜ 版本 0.16.0（T18）
覆盖率 · 条数 52/52（100.0%）｜加权 280/280（100.0%）· platform 20/20 · 条目 72/72 · 缺口 0
自检 · 离线 751/751 ｜ 完整 834/834（失败 0 · 跳过 0）
```

**一个对照（最能说明问题的一句）**：

> 「监控装好了没有？」—— 以前看**进程在不在**、**端口在不在听**。
> 这里不看这些：它问 **Prometheus 自己**「你抓的目标现在健康吗」、问 **Alertmanager**「你决定投递的是哪几条」。
> ★ 而且**必须问对那一方** —— 问错了会得出**相反**的结论（§3 第 6 站会现场演这个）。

## 档二 · 10 分钟主线（九站）

### 第 1 站 · 纳管一台新机器 —— 1 分 30 秒 ⭐ 最值得讲的一段

**问题**：以前要用这套工具，得先去目标机改 `authorized_keys`。
用户原话：「**为了用你这个工具，还要自己去改公钥，不是本末倒置吗**」。

**动作**：界面右上角 **「信任此主机」** → 填 IP / 端口 / 账号 / 名字 / 角色 → 走 6 步。

| 步 | 做什么 | 怎么自证 |
|---|---|---|
| 1 | 预检 | 22 端口可达？该 IP 是否已纳管（重复要提示，不硬覆盖） |
| 2 | 铺公钥 · 起**一次性内网分发点** | 绑管理机内网 IP + **随机路径** + **一次性 token** + **120 秒兜底** |
| 3 | ★ **生效校验：真登录** | `hostname` / `id -un` / `uname -r` 三条真跑通才算过 |
| 4 | 关停分发点 | ★ **用完即停**：公钥被取走就自动关，不靠人收尾 |
| 5 | 写 `hosts.yaml` | **写前自动备份**原文件 + 写后格式校验 |
| 6 | 自动体检 | 纳管完直接给你这台机器的**第一份体检报告** |

**现场要强调的两句诚实标注**：
① 路径 A **消灭的是"改公钥"这件事**（你不需要理解公钥是什么），**但还没消灭"去控制台粘一条"**；
② 关停是**自证的**，不是"我说我关了"：`TCP 198.51.100.1:57728 SO_ERROR=10061`（非 0 = 无监听）｜
HTTP 取公钥失败 ｜ serve 线程存活=False。

**紧接着演反例（30 秒，加分项）**：公钥写错会怎样？
**答**：**4 秒内判失败**，原因明确（认证失败 + 让你先查什么），且 `hosts.yaml` **逐字节没变**。

> ★ 这一段的价值：**它能证明"自证"不是摆设** —— 正是因为它要求"真登录"，才把状态机的一个真缺陷照了出来
> （早期状态机会一直等到 120 秒超时，还每 3 秒重复登录、刷目标机日志；修法是"认证被拒连续 2 次即判失败"）。

**证据**：`开发记录\交接\T4-收口与度量-结题回执.md`｜`证据\T4-纳管-*`（正例 / 反例 / 修复前复现）

### 第 2 站 · 一键体检 —— 1 分 30 秒 ⭐ 主线能力

**问题**：一台机器"现在好不好"，以前要敲 10+ 条命令自己拼。

**动作**：点 **「体检」** 页签 → 勾 4 台 → **开始体检**（4 台并发约 6 秒）。

**三层结构**（这是它区别于"把只读动作串一遍"的地方）：
1. **总判**：`🔴 要处理 · 🟡 注意 · 🟢 通过 · ⚠️ 无法判定`
2. **每项判定都带阈值回显**：本次用的阈值 + 出处（`config.yaml → checkup.thresholds`，**改阈值不用改代码**）
3. **每项都给"先去查什么"** → 直接指向对应单动作

**12 项**：时间同步 / 磁盘水位 / inode 水位 / 服务失败项 / 内核报错与 OOM / SELinux 模式 / 防火墙 /
证书工具链 / 包管理可用性 / 容器运行状态 / K8s 节点状态 / **最近备份是否可用**。
★ 最后一项是设计上的小心思：**护栏本身也是被体检对象** —— 备份不在了，说明护栏塌了。

**演一个"缺工具不拖垮报告"（30 秒）**：三台 K8s 上**没装 `openssl`**，这一项标
「⚠️ **无法判定** + 三步建议」，**其余 11 项照常出**；同一项在 `docker-01` 上工具链齐全 → 判绿。
★ 同一份报告里两种结果并存，这才叫"可判定"。

**证据**：`证据\T4-体检-*`（4 台并排原始响应 + 红档 + 缺工具降级）

### 第 3 站 · 变更 + 备份 + 恢复 —— 2 分钟 ⭐ 最能体现"敢用"

**问题**：改配置最怕"改坏了回不去"。

| 步 | 动作 | 看点 |
|---|---|---|
| 1 | 点一个可恢复变更动作（如 `cron.upsert` / `file.push`） | 🟡 **只需点一次确认**，不需要手输确认词 |
| 2 | 看**改动前自动备份** | 动作一声明 `backup:`，引擎在**任何变更步骤之前**备份；**备份失败即中止动作** |
| 3 | 看备份落点 | 目标机 `/var/backups/aoc/<任务ID>/` **＋** 管理机 `repo/var/backups/<任务ID>/`（**双份**） |
| 4 | 进「历史」→ 任务详情 → **恢复** | 恢复要**手输确认词**（🔴 级门槛） |
| 5 | 看恢复自证 | 恢复后 **sha256 与备份逐字节比对** |

**要强调的边界**：★ **明确不做自动回滚**。自动还原可能把"其实没坏"的现场也覆盖掉 ——
所以只做「备份 + 可一键恢复」，**把决定权留给人**。

**硬规矩**：**破坏性动作禁止批量**（**不提供开关**）；**批量不是事务** —— 每台独立执行、独立留证、各自负责。

**证据**：`开发记录\交接\T3-变更类动作与批量执行-结题回执.md`（含 §8 补遗）｜`证据\T3-*` / `证据\T4-T3尾巴-*`

### 第 4 站 · 服务目录：一键部署一个服务 —— 2 分钟 ⭐ 第二阶段的核心

**问题**：装一个 Nginx / 数据库 / NFS 服务端，以前要抄一屏命令 + 改一堆配置 + 处理 SELinux 与端口。

**动作**：点 **「服务目录」** → 选服务 → **填 5~8 个空** → **计划预览**（人可看要做什么）→ 执行。

**四件必演的事**：

| # | 演什么 | 看点 |
|---|---|---|
| 1 | **幂等** | **原样再跑一次 ⇒ 变更清单为空**（"没变"是可断言的，不是感觉） |
| 2 | **真探活的健康检查** | 不是"服务 active 就算好"：数据库要 `PING` 回**全等**、NFS 要真问导出、Web 要真的 HTTP 200 **并且端口真的开着** |
| 3 | **三个反向按钮** | 停止 / 卸载·保留数据 / 卸载·全删 —— **都真跑过**；全删要**手输确认词**，且报告逐项说清**"回不去的"** |
| 4 | ★ **引擎零改动** | 加第 2、第 3 个服务（MariaDB / Valkey / NFS）时**只写了 YAML + 模板**，`app\` 一行没改 |

**要讲的边界（诚实）**：容器路线在**本环境走不通**（公网镜像仓库三台全不可达 + 本地仓库没有业务镜像）⇒
走了包管理路线；而且 RHEL 系自 10 起用 **Valkey 取代 Redis**，所以配方名字必须是 `mariadb` / `valkey`。
★ 这不是"设计偏好"，是**实测把答案逼出来了**。

**可选加演（30 秒）**：`pkg.rollback` —— ★ 报告里一直承诺的「回退：`dnf history undo <事务号>`」，
现在**有一个动作真能做它**，并且**自证"版本逐字回到变更前"**（事务 46 → 反向事务 47）。

**证据**：`开发记录\交接\T5-配方引擎与首个服务-结题回执.md` · `T6-服务铺量-结题回执.md` ·
`T7-服务治理与扩展点-结题回执.md`｜`证据\T5-*` / `T6-*` / `T7-*`

### 第 5 站 · K8s：建起来 + 管住它 —— 1 分 30 秒 ⭐ 第三阶段

**问题**：裸装的 Rocky 到 Ready 的集群，官方文档十几步；日常还得开终端敲 `kubectl`。

**动作 A（建）**：选配方 `k8s-init` @ 控制面 → 一键；再到每个工作节点跑 `k8s-join`。
★ **"一次点击"的真实形态是两次点击** —— 因为**配方只在一台机器上执行**，而"一个集群"横跨三台。
**这是口径修正，不是缩水**（写在 `阶段开题单\T8-K8s建集群.md` §10.2.1 修订记录 #6）。

**必演的两个"只增不减"的闸门**：

1. ★★ **幂等守卫**：「预检不成立 = 已达终态」⇒ **再点一次** ⇒ 变更清单为空、
   关键 Pod 的 `RESTARTS` **前后逐项相同**、节点 `AGE` 连续。
2. ★★ **"该不该拆"有一个所有权落点**：`kubeadm reset` 不可逆，而"这个集群是不是我们建的"
   是**观测回答不了的问题** ⇒ 用标记文件 `/etc/kubernetes/aoc-owned.json` 回答它。

**动作 B（管）**：点「K8s 管理台」页签 —— 六块卡片（节点 / 工作负载 / Pod / 配置存储 / 排障 / 证书），
每块**一键取结论**。选一变更动作演示（如扩缩容）：**按一下就有终态判据**（不是"命令返回 0"）。

**演一个"逃生口只读是结构，不是文档"（20 秒）**：`k8s.kubectl` 的 `verb` 是**受控枚举**、
**没有 `flags` 参数** ⇒ `-o yaml` **物理上不可达**；三条写动词全被拒，**且拒绝信息里带着作者写的
"请用对应的动作"**。

**证据**：`开发记录\交接\T8-K8s建集群-结题回执.md` · `T9-K8s管理台-结题回执.md`｜`证据\T8-*` / `T9-*`

### 第 6 站 · 监控告警：能证明它在工作 —— 1 分钟 ⭐ 第四阶段 · 最值钱的一段

**问题**：「监控装好了没有？」—— 以前只能看进程在不在、端口在不在听。**这些都不算。**

**动作**：点「监控告警」页签 → 六块一键取结论（总览 / 抓取目标 / 规则 / 当前告警 / 抑制 / 收端）。

**三条判据各自问对那一方**：

| 问题 | 问谁 | 什么不算 |
|---|---|---|
| 指标**在采**吗 | Prometheus **自己的** `/api/v1/targets` 的 `health` | 配置文件里写了几个目标 · `systemctl is-active` · 端口在听 —— **三个都不算** |
| 规则**在判**吗 | `/api/v1/rules` 与文件**逐条对账** ＋ `for` 的**三跳状态迁移**（造条件前 `inactive` → 造完 `pending` → 过了 `for` `firing`） | 只查一次看到 `firing` **证明不了 `for`**；"重载成功"看的是配置重载标志位，**不是 `curl` 返回 200** |
| 告警**真的送出去了**吗 | **收端留证**（带接收时间戳的 append-only 记录） | 配了 webhook 地址 **不算** |

★★★ **压轴一句（本阶段最值钱的发现）**：
**抑制只能问 Alertmanager。** 同一时刻，Alertmanager 说「`active 1` / `suppressed 1`」，
而 Prometheus 说「`firing 2`」—— **因为它俩回答的根本不是同一个问题**（抑制是**投递前**的决定）。
⇒ **用错接口会得出"抑制没生效"这个相反结论。**

**要讲的边界（诚实）**：`Grafana` 首次登录要改密码，★ **这一步只能人做** ——
报告与界面都**明说了**，**没有假装完成**。

**证据**：`开发记录\交接\T10-监控告警接入-结题回执.md`（★ §5「踩过的坑」十三条）｜`证据\T10-*`

### 第 8 站 · AI 助手：从「人话」到「带证据链的报告」 —— 2 分钟 ⭐ 第五阶段收口

**要讲的四个设计点**：
1. ★★ **AI 与点击走同一个接口**：AI 侧只拿得到 `api.dispatch` **这个函数本身** ——
   「AI 只能走 `/api/**`」不是一句承诺，是**唯一可用的通道**（有静态断言看着）。
2. ★★ **「请求」是 AI 的权利，「执行」不是**：`yellow` 只可**请求**（白名单 10 个）、
   `red` **连请求都不许发**；卡片五要素**全部由平台填**；人点了确认才走**既有那条路**。
3. ★★ **报告 = 索引 + 结论**：每一条结论都挂**任务号** ⇒ 顺着能看到自证、步骤、**原文归档**。
   三种情形必须如实写：`pending` ⇒「未执行（人还没点确认）」· `rejected` ⇒「未执行（人驳回了）」·
   复核没成立 ⇒「**未证实**」；★ 拿不到任务号的 ⇒「**没有任务号（不可回放）**」，**不许混进结论区**。
4. ★ **报告不许说假话**：生成前**自己扫一遍**，出现「已修复 / 已完成」⇒ **拒绝生成**；
   ★ 报告**不内嵌目标机原文**（它是会被转发的东西）；时间线里**变更看得出来**（「执行（变更 · yellow）」）。

**现场怎么演**（★ 用「报告」页签）：
**动作 A**：选一个会话 → 报告预览 → 顺着一条结论点开它的**任务号** → 看那一步的自证与归档。
**动作 B**：在检索框里问「上次这类问题是怎么解决的」→ 命中会给**出处四要素**；
★ 查一个不存在的词 ⇒ 它会说「**没有记录**」并**交代查了哪些范围**（不是一句「没查到」）。
**动作 C**：点「扫 Recipe 候选」→ 草案落在 `repo\var\lab\recipes-candidate\`，
★ 返回里有一行 `recipes_untouched: true`（**`catalog/recipes/` 一个字节都没动**）。

**复算**：`python tools\selftest.py --offline` 的「v1.20（T17）」一节 ——
★ T15 的 **Ⓐ~Ⓘ ＋ Ⓛ 十条** ＋ T16 的 **Ⓙ Ⓚ Ⓜ Ⓝ Ⓞ Ⓟ Ⓠ Ⓡ Ⓢ Ⓣ Ⓤ 十一条** ＋ T17 的 **Ⓥ Ⓦ Ⓧ Ⓨ Ⓩ Ⓩa Ⓩb Ⓩc Ⓩd 九条**，**全离线可跑**；

### 第 9 站 · 虚拟机：把「机器的开关」也收进闸门 —— 1 分 30 秒 ⭐ 第六阶段

**讲一句**：到这一站为止，工作台管的是**机器里面**的东西（进程 / 服务 / 集群 / 监控）。

**现场怎么演**（★ 用「虚拟机」页签）：

- **动作 A（看）**：页首第一行就写着**执行面是宿主机** —— 这些动作跑在**本机 `vmrun.exe`** 上，
  **不是** ssh 到顶栏那台机器。★ 再点四块「一键取结论」：**清单（含归属）· 状态 · 地址 · 快照链**。
