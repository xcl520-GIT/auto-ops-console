## 5. ★★ 遗留与本阶段"只增不减"的一处口径

1. **"一键到 Ready"是两次点击**（控制面一次 + 每个工作节点一次）—— ★ 配方**只在一台机器上执行**，
   而"一个集群"横跨三台；硬做成一次就得让配方去 ssh 另外两台（等于在配方层开后门）。
   ★★ 已记入开题单 §10.2.1 修订记录 #6，**是口径修正不是缩水**。
2. **两份 k8s 配方都是 `red`** ⇒ **都禁止批量** —— 因为它们都含 `kubeadm reset`（"拆与建必须同一次"，§12.32.7）。
   ★ 后果如实写：工作节点要**各点一次**。
3. **`token` / CA 指纹会进报告与配置** ⇒ 只适用于实验环境；换生产走"短期 token + 手动确认"。
4. **存储类的后端与实物不同**（节点本地目录 vs NFS），因为 `/data/nfs` 是红线 B1。★ 差异三项已逐条写明。
5. **`node02` 上仍留着 S2 写的 5 份 `99-aoc-*.conf`**（3 份 sysctl + 2 份 modules-load）——
   ★ 它们是"S2 真的写了盘"的旁证，**本阶段没动**；★ 若要"回到今天这个现场"，它们**要单独说清留不留**。
6. **`ghcr.io` 在 S4 那次采样掉到 000** —— 本阶段没用到它（组件走阿里云、Calico 走本地缓存）。
7. ★★ **集群现在活着**（三节点 Ready）—— 按 T5~T7 的老规矩「**先留证 + 推送 GitHub → 再定是否保留集群**」：
   ★ 本阶段的证据已全部落盘、代码已推送；**集留守/拆由用户拍板**（拆的入口是 `k8s.kubeadm-reset`，red）。

## 6. 坑（T8 新增，血换来的）

| # | 坑 | 一句话 |
|---|---|---|
| 1 | ★★★ **"契约与实现不一致、且不一致的方向更松"** | `ok_exit_codes` 的注释写着会红、**实际从来没红过**（六个老动作一直在假绿）。★ 为什么没被发现：**它们都真的做成了** ⇒ "对"的结果掩盖了"错的判据" |
| 2 | ★★★ **"判据写对了没有"，只有遇到"它本该红"的场景时才验得出来** | 幂等守卫是第一个"要求命令必须失败"的场景 ⇒ 它一出现，上面那条立刻现形 |
| 3 | ★★ **"跑完了" ≠ "事情成了"（第三、四次现形）** | ①②：`cmp -s` 成功即空输出 ⇒ `raw` 给 `None` ⇒ 自证假红；大文件走内联命令行 ⇒ 控制台自己炸（看着像"平台坏了"）。③ ★ **自检自己的收尾**：`svc.stop` / `file.remove` 被确认词拒掉，而收尾函数**照样打印"夹具已收干净"** |
| 4 | ★★ **跨状态的配方必须把"起点"和"终点"都包进来** | 只写终点，起点会被当成终点（旧集群 `Ready` 会给绿灯）⇒ **假绿** |
| 5 | ★★ **守卫挂在「步骤」上，不挂在「动作」上** | 一个动作的多条预检**语义不同**：缺工具永远不是"已达终态" |
| 6 | ★ **幂等守卫解决的是"预检不成立"这一种**，不是"任何失败" | 它只在 `aborted` + `PRECHECK_FAILED` + **恰好那一步** + 有理由 时生效 |
| 7 | ★★ **红动作的确认词要"从定义里取"，不要硬编码** | 文案一改，硬编码就静默失效（而失效的样子是"被拒"而不是"报错"） |
| 8 | ★ **"自己铺的夹具自己收"，而且收完要自己验** | ★ 收尾跑完 ≠ 收干净（见坑 #3 ③） |
| 9 | ★★ **大文件不许走命令行** | 管理机是 Windows ⇒ `CreateProcess` 约 32K 上限；超过就走 scp + **原子 `mv`** |
| 10 | ★ **改了 `app\` 必须重启**（本阶段重启了 5 次） | `app\` 是内存里加载的；★ 而**配方**可以热装载 —— 两者的区别别混 |
| 11 | ★ **`ls -ld <path>` + `ok_exit_codes: [2]` 才是"它不在"** | 用它做"必须失败"的预检 —— ★ 但**前提是坑 #1 修好了** |
| 12 | ★★ **别拿"输出行首字段"当"全都成立"的判据** | `kubectl wait` 的输出行首是**节点名**，一个 Ready 就够撑一行 ⇒ **退出码**才等价于"全部就绪" |
