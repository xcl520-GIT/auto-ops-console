## 4. ★ 唯一的卡点：`sec.avc` 的 `ausearch` 在引擎链路里必超时

**现象**：`denials` 步骤固定挂满超时（先 60s、后放宽到 150s，都是 `超时 + 8s 连接 + 2s` 才被杀）。

**已确认的事实（不要再重复验证）**：

| 项 | 实测 |
|---|---|
| 引擎发出的命令原文 | `env LC_ALL=C LANG=C ausearch -m avc -ts recent`（在 `ops.db` 的 `argv_quoted` 里逐字可查） |
| 手工/脚本直跑**同一条命令** | **20~40 ms** 返回，`rc=1`，stderr `<no matches>` |
| ausearch 慢吗 | ❌ 不慢。`-ts recent` / `-ts today` / 不带 `-ts` 全都在 40ms 内（用 `date +%s%N` 前后计时） |
| auditd 状态 | `active`（不是"没跑所以查不到"） |
| 审计日志大小 | `audit.log` **7.8 MB**（不大，不是扫大文件慢） |
| `rpm -q` / `journalctl -g` 的退出码坑 | ✅ 已修（见 §6 坑 2、3） |
| 目标机整体 | `203.0.113.100` 通、免密可用、RHEL 10.0、`is-system-running=degraded`（T1 夹具） |

**结论**：挂起点**不在 ausearch**，而在 **ssh 调用形式**或**stdin 传递**。

**下次第一件事：bisect ssh 调用形式**（那次对比被中止，未拿到结果 —— 重现命令如下，逐条计时）：

```powershell
$cmd = 'env LC_ALL=C LANG=C ausearch -m avc -ts recent'
# A：与引擎完全一致（-T + 全部 -o + 指定密钥 + 隐式 stdin）
ssh -T -o BatchMode=yes -o ConnectTimeout=8 -o StrictHostKeyChecking=accept-new `
    -o ServerAliveInterval=15 -o ServerAliveCountMax=3 -i "$env:USERPROFILE\.ssh\id_ed25519" `
    root@203.0.113.100 $cmd
# B：不带 -T
ssh -o BatchMode=yes -o ConnectTimeout=8 root@203.0.113.100 $cmd
# C：远端显式重定向 stdin
ssh -T -o BatchMode=yes root@203.0.113.100 "$cmd < /dev/null"
# D（最可疑）：让它显式指定输入文件，绕开 stdin 行为
ssh -T -o BatchMode=yes root@203.0.113.100 "$cmd --input /var/log/audit/audit.log"
```
> 猜测排序：**D > 变体 stdin** > `-T` > `-o` 组合。若 D 立刻返回，则真正原因是
> "ausearch 在 stdin 非终端时的行为"（它可能把 stdin 当作输入源并一直等 EOF），
> 修法就是在动作 YAML 里给该步骤加 `--input /var/log/audit/audit.log` —— 不需要改代码。

**不要**用 `journalctl -g avc` 替代：auditd 在跑时 AVC 记录**不往 journald 写**，会给出"干净"的假结论。

## 6. 踩过的坑（★ 下次别踩，按价值排序）

| # | 坑 | 症状 | 怎么绕 |
|---|---|---|---|
| 1 | **PowerShell 5.1 的 `Get-Content`/`Set-Content` 按 GBK 处理 UTF-8 文件** | 我用 `-replace` + `Set-Content` 改 `timer.list.yaml`，**整份文件被写成乱码**（中文全变 `瀹氭椂`），只能删掉重写 | 改这些文件**只用**助手工具（`writeFile` / `editFile`），**绝不用 PowerShell 去做文本替换**。已实际踩到一次并重写恢复 |
| 2 | **`journalctl -g` 过滤无匹配时退出码是 1** | `kernel.log` 的 oom 步骤被判 `STEP_FAILED`，整个动作 failed | 声明 `ok_exit_codes: [0, 1]`（和 grep 一样：没有匹配就是"没有"）。**探针时误判过**——因为 `rc=$?` 取到的是管道尾 `head` 的退出码 |
| 3 | **`rpm -q <多个包>` 的退出码 = 没查到的包个数** | `pkg.search` 的 tools 步骤 rc=3（缺 bind-utils/traceroute/mtr 三个）→ 被判失败 | `ok_exit_codes: [0..9]` 全声明（它本来就只是"点名"信息） |
| 4 | **YAML 双引号会把 `\t` `\n` 变成真字符** | `"-printf", "%s\t%p\n"` 里 `\n` 成了真换行 → 加载校验报"含 shell 元字符" | 用**单引号** `'%s\t%p\n'`（我们要的是字面量，交给 find 自己解释）。**这次是被加载期校验拦下的 —— 证明那道防线有效** |
| 5 | **`ps -e ... -u <用户>` 不按用户过滤** | `-e` 的选择范围压过 `-u`，列出的还是全部进程（连 `-u nobody` 都一样） | 按用户过滤时**不带 `-e`**，并且整条命令用 `when` 整体挂起（没填用户就整步跳过） |
| 6 | **`systemctl show <PID>` 不可用** | 报 `Failed to get properties: Unknown object '/org/freedesktop/systemd1/job/1800'` | 用 **`ps -o unit= -p <PID>`** 反查单元 —— 这是"端口→归属服务"唯一可行的桥 |
| 7 | **`nmcli -f DEVICE,...` 字段名非法** | `Error: 'device show': invalid field 'DEVICE'` | 必须用带前缀的字段名：`GENERAL.DEVICE,GENERAL.STATE` |
| 8 | **`ausearch -ts today` 在真实审计日志上可以很慢/挂住**（本机实测 70s+ 起） | 默认"今天"会让动作超时 | 默认范围改成「最近 10 分钟」，并把该步 `timeout` 放到 150s（**真正的挂起原因见 §4，与范围无关**） |
| 9 | **探针脚本会被环境截断** | 第二批探针输出只到 `### 22 avc` 就没了（后面全丢） | 探针**分段跑**，每段加 `timeout`；关键命令单独再跑一次核对 |
| 10 | 解析器"能切出 6 列"就当套接字行 | `ss_rows` 把 `"this is not a socket line"` 解析成了套接字 | 加**结构校验**：第一列必须是已知协议、local 必须形如 `地址:端口`；整段都不过才报错 |
