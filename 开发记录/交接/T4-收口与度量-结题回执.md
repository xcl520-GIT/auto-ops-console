## 1. 做了什么（按主线顺序）

### 1.2 主线 1：`host.enroll` 主机纳管（用户点名的痛点）

> 兑现用户原话：「以后为了用你这个平台工具，还要自己去改公钥，不是本末倒置吗」

- **走零依赖路径 A**（开工前已拍板）：界面起一个**一次性内网分发点** —— 绑管理机内网 IP +
  **随机路径** + **一次性 token** + **用完即停** + **120 秒兜底**；给用户**一条**现成命令去目标机控制台粘。
- 6 步流程，每步都看得见：**预检 → 发公钥 → ★真登录校验 → 关停分发点 → 写 `hosts.yaml`（写前备份）→ 自动体检**
- **界面入口**：顶部「信任此主机」（不是新页签）
- ★ **诚实标注**（也写进了 `map.yaml` 状态）：它消灭的是"**改公钥**"这件事，**还没消灭**"去控制台粘一条"。
  要彻底消灭只能靠路径 B（填密码全自动），而管理机是 Windows OpenSSH、**没有可用的非交互密码通道**
  → 已评估后**明确不做**，不硬凑。

### 1.3 主线 2：覆盖率换"加权分母"（让数字经得起追问）

- `map.yaml` 新增 **`weights:` 段**（**一处集中**，50 条），每条 `w`(1~5) / `src` / `why`（**必须有出处**）
- ★ **`platform:` 段纳入加权分母**（6 条：回放 / 自动备份 / 恢复 / 批量 / 纳管 / 导出）——
  它们是天天在用的东西，此前的条数口径**一条都不算**
- `platform:` 段改判 `done: true/false`（**显式布尔**，不靠中文 `status` 文本匹配）
- `catalog.py::reconcile` 出**双口径**，页面**并列展示** + 权重来源角标 + 缺口按权重降序
- 定权规则：`P0=4 / P1=3 / P2=2 / P3=1`，平台能力基准 4；**只有"记录里有名有姓的点名"才 +1**；
  **不设 −1**（"做得不够好"进待办，不进权重）；**不衡量"当前环境跑不跑得通"**
- ★ **全部标注「反推」**，不冒充用户原话

### 1.4 主线 3：`checkup` 一键体检

- **一个动作 + 一层判定**：采集走 `catalog\actions\host.checkup.yaml`（20 步），
  判定走 `app\checkup.py`（**12 项**）—— ★ **不让 YAML 承担逻辑**
- **阈值进 `config.yaml` 的 `checkup:` 段**，报告里**回显用的是哪一档**（改阈值不用改代码）
- **每项都给"先去查什么"**（指向对应单动作），不做纯数据堆砌
- **单机 + 4 台并排**（复用批量框架、失败隔离）+ **导出 md/txt**
- **缺工具降级不拖垮报告**：三台 K8s 没装 `openssl` → 该项"⚠️ 无法判定 + 三步建议"，其余项照常出
- 第 12 项是**"最近备份可用性"**——护栏本身也是被体检对象

## 5. 踩过的坑（★ 下次别踩）

### 5.1 ★ 收尾时抓到的四处真错（本回执的"含金量"主要在这）

| # | 坑 | 怎么发现的 | 修法 / 教训 |
|---|---|---|---|
| 1 | ★ **`map.yaml` 里 `host-enroll` 的 `done` 还是 `false`**，而纳管**已交付、正反例都跑过** → 页面显示 **177/191**，**比事实少 5 分** | 收尾做"开工时点 vs 收尾时点"对账时，逐项核缺口清单 | 改 `done: true` → **182/191**。★ 教训：**`entries` 段靠"动作文件是否存在"自动对账，而 `platform:` 段是显式布尔 —— 没有任何机制会替你发现它没更新。交付一个新能力时必须同时回填账本。** 已入规范 §10.3.4（双时点对照表）+ §11（`v1.5 勘误`） |
| 2 | **页首版本号停在 `T3 · v0.3.1`**，而 T4 已新增 6 条路由 | 拍界面截图时看到页首 | `__version__` → `0.4.0`、`__stage__` → `T4`，重启后页首可验。这是 T3 立下的规矩：**接口面变了，必须能一眼分清跑的是哪一版** |
| 3 | **自检把已入 Git 的 4 个夹具写成 CRLF**，每次跑完 `git status` 冒假改动 | 收尾看 `git status` 发现 4 个 ` M`，但 `git diff` 为空 | `tools\selftest.py` 两处 `write_text` 加 `newline="\n"`。★ 与规范 **§9.12 同一族坑**：Windows 换行会把"没变"变成"看起来变了" |
| 4 | **`var\lab\` 里自检/演练生成的临时物没被忽略** | 同上（`?? _selftest_enroll.pub`） | `.gitignore` 补 `var/lab/_*.pub` / `var/lab/_*.yaml`（**脚本留着，产物不留**）。顺带把 `var\` 根的 22 个临时脚本挪进被忽略的 `var\artifacts\_t4-scripts\` |

> ★ 这里有一条同族规律值得记：**"看起来没问题"和"确实没问题"之间，隔着一个"有没有人去核"**。
> #1 是账本没人回填，#2 是版本号没人看，#3/#4 是没人看 `git status` 的每一行。

### 5.2 开发过程中踩的坑（已写入规范 §10.4~10.6）

| # | 坑 | 教训（规范位置） |
|---|---|---|
| 1 | `precheck:` 段**一直在用**（8 个动作），却从没写进字段表 | §2.8 + §10.4 —— **"一直在用"不等于"已经定义"** |
